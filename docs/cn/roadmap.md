# 路线图（完整计划书）

本文是项目从现在到 v0.4 的完整计划。架构决策（ADR-1 至 ADR-9）的理由见 [迁移方案](cn-migration-plan.md)，每一步的过程和结果见 [工作记录](worklog.md)。计划会随实现调整，调整时同步修改本文。

## 1. 目标

在上游 AI Job Search 的基础上，做一个面向国内实习和校招的本地求职助手。用户自带 Codex 或 Claude Code（ADR-7、ADR-8），数据只存在本地（ADR-6）。

首版闭环：**导入中文 JD → 结构化提取 → 个人档案匹配 → 中文简历生成与审核 → 岗位状态保存**。

长期方向（ADR-9）：发现岗位 → 筛选评估 → 准备材料 → 投递 → 跟进 → 面试练习。凡是涉及平台规则或对外发送的环节，都必须经用户确认。

## 3. 里程碑

### v0.1：中文 JD 入库（第 1 周）

**第 3 步：存储与去重（`store.py`）**

- `python -m jobsearch_cn jd save` 和 `jd list` / `jd show` / `jd status`，输出 JSON。
- 用 `data/jobs/*.json` 存储（每条一份文件，便于查看和比较）。SQLite 推迟到 v0.2：等匹配和筛选真正需要查询时再接，放在同一套接口后面。
- 去重（G2）：内容指纹（`id`）> 规范化后的来源 URL；可信岗位 ID 等 v0.3 接入门户、Schema 有了对应字段再加。重复导入逐字段合并，不产生新记录。
- 保存前必须通过 `jd validate`。
- 验收：重复导入同一份 JD 不产生重复；状态修改可追溯；`data/` 不进 git。

**第 3 步：Agent 入口**

- Claude Code：`.claude/skills/cn-jd-import/SKILL.md`。`allowed-tools` 只用 `ALLOWED_SKILL_TOOLS` 中的条目；`python -m jobsearch_cn …` 同时登记到 `settings.json` 和 `security_guards.ALLOWED_PERMISSIONS`（ADR-3）。
- Codex：在 `AGENTS.md` 的 CN 段落写调用说明。工作流只写一份，另一端引用。
- Agent 补全规则留空的字段时 `method` 写 `agent`，出处片段必须来自原文，再交给 `jd validate` 把关。
- 实测 ADR-7 的两个问题：Claude Code 是否读取 `AGENTS.md`；Codex 能否发现 `.agents/skills/` 以外的技能。
- 验收：两个 Agent 都能完成"粘贴 JD → 解析 → 补全 → 校验 → 保存 → 查询"。

**第 4 步：测试与发布**

- 补测试：空文件、超长文本、GBK、重复记录、中文注入、缺失字段；5 份样例端到端走完解析、保存和查询。
- 更新文档，打 tag `v0.1.0`。
- 验收：上游测试没有新增失败；CI 在 Python 3.10–3.14 和 Windows 上通过。

### v0.2：档案、匹配与中文简历（第 2 周）

- **个人档案**：`data/profile/`（不入库），格式为 JSON 或 YAML，字段包括届别、学历、城市偏好、可到岗天数、实习时长、技能和经历。提供一个不读写上游 `CLAUDE.md` 的 CN 版 setup，并加测试检查上游模板仍是占位符（ADR-6）。
- **硬性条件过滤**：届别、学历、城市/远程、每周天数、实习时长。不符合的列出原因；字段为 null 时标为"未知"，不判为不符合。
- **可解释评分**：技能命中、方向匹配、薪资、转正等，每一项都给分值和依据，复用上游 `/rank` 的打分思路。
- **中文简历**：先决定格式（待决事项 1）。倾向 LaTeX + ctex/xeCJK 输出一页简历，另评估 DOCX 导出。沿用上游"起草 + 审核"的双 Agent 流程和核验清单，事实不得超出档案。
- **打招呼语 / 求职信**：短文本模板，针对 BOSS 直聘打招呼和邮件投递两种场景。
- 验收：一份样例 JD 能得到过滤结论、评分解释、一页中文简历 PDF 和打招呼语，审核清单全部通过。

### v0.3：编排、成本与合规来源（第 3 周）

- **多 Agent 编排**：导入、补全、匹配、起草、审核串成一个工作流，并写明另一端的降级做法（ADR-7）。
- **日志与成本**：`logs/` 记录每一步的耗时、结果和 Token。Token 用量以各运行时自己的数据为准（ADR-8）。
- **单链接读取**：用户给出单个公开岗位链接时，由 Agent 只读这一页，遵守 robots.txt（ADR-9 第二层）。
- **合规来源**：按 `/add-portal` 规范逐个接入公司官网和招聘系统（Moka、飞书招聘、各大厂官网），接入前确认用户协议、公开访问、无需绕过防爬三点。放在 `.agents/skills/`，由用户触发、低频访问。
- 验收：至少接入 1 个经核实的来源；完整跑一遍有成本记录。

### v0.4：看板与发布（第 4 周）

- **求职看板**：复用上游 `/html-report`，或做一个轻量的本地页面，展示岗位状态、投递进度和跟进提醒。
- **跟进**：状态流转（已投递 / 面试 / offer / 拒绝），复用上游 `/outcome` 和 `/interview`。
- **回归测试与脱敏演示**：端到端演示脚本和演示数据全部脱敏。
- **技术文档**：架构、使用指南、贡献说明；整理可以回馈上游的改进（例如中文注入句式）。

### v0.4 以后（可选，用户自行决定）

- 招聘平台站内自动化（ADR-9）：只作为默认关闭、不公开的个人模块。护栏包括真人节奏、每日上限、发送前批量确认、遇验证码即停。
- 邮箱投递与回执同步（参考上游 `/gmail-sync`）。

## 4. 不做的事

破解验证码、伪装浏览器指纹、逆向平台加密参数、索取或保存平台账号/Cookie、未经确认的批量投递、托管服务或提供模型 API。

## 5. 工程约定

- 每一步一个分支、一个 PR；合并前本地全量测试、`security_guards`、`lint_skills` 都要通过，并在工作记录追加一条。
- `jobsearch_cn` 只用标准库、不联网（`tests/test_cn_package.py` 守护）；允许导入的上游工具用白名单显式列出。
- 上游文件尽量不动（ADR-1）；按 [迁移方案 §6](cn-migration-plan.md#6-上游同步流程) 定期同步上游的发布 tag。
- 本地测试命令：`conda activate ai-job-search-cn`，然后 `python -m unittest discover -s tests -t .`。

## 6. 风险与待决

| 项 | 影响 | 应对 |
| --- | --- | --- |
| 中文简历格式（LaTeX CJK 或 DOCX） | v0.2 的简历产出 | 第 2 周开始时做原型对比后决定 |
| 规则覆盖有限（城市列表、技能词表） | 字段留空较多 | Agent 补全 + `jd validate` 把关；按真实样例逐步扩充 |
| 上游 Bun 1.4.4 导致 4 个 CI 红灯 | CI 噪音 | 等上游修复，见基线报告 §4.1 |

| 平台用户协议变化 | 来源接入 | 每个来源接入前复核，记录在工作记录 |
