# 路线图

本文是项目**唯一的任务清单和进度表**。计划分两层：

- [总体规划](master-plan.md)：最终目的、原则、每个里程碑的目标和完成标准、待决事项、分工。很少改动。
- 本文：把里程碑拆成可以勾选的任务，标明负责人、交付物和验收标准，随每个 PR 更新。

过程和结果写在[工作记录](worklog.md)，版本变化写在 [CHANGELOG](CHANGELOG.md)，架构决策的理由写在[迁移方案](cn-migration-plan.md)。

## 怎么用本文

- **负责人**：`用户` 做决定、合并 PR、自用验收；`规划` 维护计划、写任务单、审核 PR；`执行` 实现、测试、写工作记录；`验证` 由 Codex 实测工作流、独立编写样例和期望结果。
- **编号**：`M2-3` 表示里程碑 M2 的第 3 项；`H` 是收尾和维护类任务。PR 标题或描述、工作记录里都要引用编号。
- **粒度**：当前里程碑拆到每个 PR；后面的里程碑只列大项，开工前由规划者细化。
- **更新规则**：
  - 执行者在每个 PR 里勾掉完成的项，写上 PR 号，更新"当前进度"；
  - 实际做法和本文不同时（字段、拆分方式、先后顺序），执行者直接按实际改写对应条目，并在 PR 描述里说明，规划者审核时确认；
  - 新增或删除任务、调整完成标准、改变里程碑范围，由规划者修改，并同步总体规划。

- [x] **M2-2** `执行` 硬性条件过滤 `match`（PR #12）
  - 按 [profile.md §6](profile.md) 的对照表，逐项比较届别、学历、每周天数、实习月数、城市与远程、岗位类型和排除项；
  - 每一项给出"符合 / 冲突 / 未知"，同时引用 JD 出处和档案条目；JD 或档案没写的判"未知"，不判"冲突"；
  - 过滤是纯计算，结果不落盘，所以本项不涉及 D4；匹配结果的存储放到 M2-4 再定；
  - 届别 `strict: false`（"优先"）不符时只给提示，不判冲突；薪资不算硬性条件，留给 M2-4 评分；
  - 授权 `Bash(python -m jobsearch_cn match:*)`，同样在三处登记。
  - **验收**：每种条件的符合、冲突、未知三种情况都有测试；5 份样例 JD × 2 份示例档案（tech、ops）共 10 组结果写成测试里的期望表，并在 PR 里附人工核对说明；变异测试关掉"null 判未知"时有测试失败。
  - 实际做法：`jobsearch_cn/match.py` 和 `match filter <岗位id>`，判定表见 [match.md](match.md)。规划者审核确认的 5 处细节：
    1. 届别 `strict: false` 不符时判"符合"并附 `note`，不影响总结论；
    2. 地点沿用 profile.md §6 的"愿意搬家"（`relocate: true` 时判"符合"并附 `note`）；只有 `relocate` 为 false，且 JD 不支持远程或档案不接受远程时才判冲突，其余判未知（审核时修正：两边都没写远程原先被误判为冲突）；"上海"与"上海市"视为相同；
    3. 排除项：关键词只匹配标题，另按 §6 检查排除的公司和排除的城市（JD 城市全部被排除才算）；
    4. 档案只做结构校验，来源文件缺失不影响过滤；
    5. 输出的结论用英文枚举：`match`/`conflict`/`unknown`，总结论 `eligible`/`needs_check`/`ineligible`。

## 11. 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 规则覆盖有限（城市列表、技能词表） | 很多字段留空，需要补全 | Agent 补全，再由 `jd validate` 把关；M2-3 把词表外置，按真实样例扩充 |
| Codex 和 Claude Code 发现技能的方式不同 | 有一端可能找不到工作流 | M1-5 实测；必要时用 `enabled: false` 的薄入口 |

| 平台用户协议变化 | 已接入的来源可能不能再用 | 每个来源接入前和每次发布前复核（M6-2） |

## 12. 工程约定

- **每个 PR**：一个 `feat/cn-*` 分支（文档用 `docs/cn-*`，维护用 `chore/*`）；本地全量测试、`security_guards`、`lint_skills` 通过；工作记录追加一条；按"更新规则"更新本文；PR 描述引用任务编号。
- **每个里程碑结束**：打 tag（推送前用户确认）；更新 CHANGELOG 和 README 的进度表；规划者写复盘，细化下一个里程碑。
- **边界**：`jobsearch_cn` 只用标准库、不联网（`tests/test_cn_package.py` 守护）；允许导入的上游工具用白名单显式列出；上游文件尽量不动（ADR-1）。
- **上游同步**：关注每周的 "Upstream sync watch" issue；上游发布新 tag 时，由执行者开 `chore/upstream-sync` 分支合并（[迁移方案 §6](cn-migration-plan.md#6-上游同步流程)），规划者先评估影响。
- **本地测试**：`conda activate ai-job-search-cn`，然后 `python -m unittest discover -s tests -t .`。
