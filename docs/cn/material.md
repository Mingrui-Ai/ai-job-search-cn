# 求职材料格式（Material v1，M3-1）

简历等求职材料先写成一份**引用档案条目的 JSON**，检查通过以后再交给渲染（M3-2）。材料只决定选哪些条目、排什么顺序、经历要点怎么改写、列哪些技能和课程；姓名、联系方式、学校、公司、职位、日期都不写在材料里，渲染时按 `ref` 从档案里取，所以材料里没有编造这些内容的地方。

本格式用 `kind` 区分材料种类。目前只有 `resume`（简历）；打招呼语、邮件（M3-4）以后沿用同一格式，另加种类。

## 1. 存放位置

`data/materials/<岗位id>/resume-<n>.json`，一份简历一个文件。`data/` 不提交。

## 2. 引用的条目 id

材料按 `id` 引用档案条目（[profile.md](profile.md#3-profilejson-字段)）：经历本来就有 `id`；教育、奖项、证书、语言的 `id` 是可选的，没有 `id` 的条目不能被引用，`material validate` 会提示先用 cn-setup 补上。`id` 在整份档案里不重复，所以引用时不用写是哪一表。技能按名字引用（档案里技能名不重复）。

## 3. 字段

例子（虚构，即 `tests/fixtures/cn/material/tech-m3/resume-1.json` 的节选）：

```json
{
  "schema_version": 1,
  "kind": "resume",
  "job_id": "job_000000000001",
  "profile_hash": "…",
  "created": "2026-11-01T10:00:00+08:00",
  "summary": {"text": "后端开发实习一段，熟悉 Go 和 Python，做过 RAG 问答服务的检索评测", "refs": ["exp-1", "proj-1"]},
  "education": [{"ref": "edu-1", "courses": ["机器学习", "分布式系统"]}],
  "experience": [
    {"ref": "exp-1", "bullets": [
      {"text": "用 Go 重构订单查询接口，P99 延迟从 120ms 降到 45ms", "refs": ["exp-1"]}
    ]}
  ],
  "skills": ["Python", "Go", "MySQL", "LangChain", "RAG"],
  "awards": [{"ref": "award-1"}],
  "certificates": [{"ref": "cert-1"}],
  "languages": [{"ref": "lang-1"}]
}
```

| 字段 | 说明 |
| --- | --- |
| `schema_version` | 固定为 `1` |
| `kind` | 材料种类，目前只能是 `resume` |
| `job_id` | 这份材料投的岗位；本地岗位库里有这个岗位时，检查会对照它的技能要求给警告 |
| `profile_hash` | 写材料时档案的摘要（和匹配记录用的是同一种），档案后来改过会给警告 |
| `created` | 写材料的时间，ISO 8601，要带时区，例如 `2026-11-01T10:00:00+08:00`（结尾写 `Z` 也行）；日期或时间不存在的不通过 |
| `summary` | 个人简介：`text` 是正文，`refs` 是它依据的条目，至少一条。没有简介时为 `null` |
| `education[]` | 列出的教育条目：`ref`，以及要列出的课程 `courses`（只能是该条目 `courses` 里有的） |
| `experience[]` | 列出的经历：`ref`，以及改写后的要点 `bullets[]`，每条有 `text` 和 `refs`；`refs` 必须包含所在经历自己的 `id`，可以再引用别的条目 |
| `skills[]` | 列出的技能名，只能是档案 `skills[]` 里有的（同义写法算同一项，不能重复） |
| `awards[]`、`certificates[]`、`languages[]` | 列出的条目，每项只有 `ref` |

所有字段都要写；某一节不列就写 `[]`。同一条目在一节里不能列两次。

## 4. `material validate`

```
python -m jobsearch_cn material validate data/materials/<岗位id>/resume-1.json [--profile <档案>] [--data-dir <目录>]
```

档案默认为 `<数据目录>/profile/profile.json`，必须先通过 `profile validate`。输出和其他校验命令一样：标准输出 `{"valid": …, "errors": […], "warnings": […]}`。不通过时退出码 1，每条错误写明 `<字段路径>: <原因>`；材料或档案读不了（文件不存在、不是 JSON）时退出码 2。

**不通过**（错误）：

- 字段缺失、多余或类型不对；
- `ref` / `refs` 在档案里找不到，或者引用了别的表的条目（例如在 `awards` 里引用证书）；
- 经历要点的 `refs` 没有包含所在经历；要点和简介的 `refs` 为空；
- 列了档案里没有的技能、该条教育里没有的课程，或者同一项列了两次；
- **改写编了数字**：要点和简介里的每个数，都必须在所引条目的原文（经历的名称、单位、职位、要点；教育的学校、专业、绩点、排名、课程；证书、语言、奖项的各项）里以同样的值出现过。阿拉伯数字和中文数字按数值比较：`120ms` 可以写成"一百二十毫秒"，`60%` 可以写成"六成"，`2万` 和"两万"相同；原文没有的数，不管是"降低 62%""快了三倍""百分之三十"还是"两万次"，都不通过。中文数字按通常的读法算值："一百零二"是 102，"一千零二十"是 1020，"一亿二千万"是 120000000，"一万二"是 12000，"三百五"是 350，"二〇二六"这种逐位写、中间有零的是 2026。报错写明是哪个数，处理办法是改回原文的数字，或者请用户把这个数补进档案。"统一""一线""三方""百度""十分""零基础""万一""亿万"这类词里的字不算数；"千万"后面紧跟"不""别""要""莫""勿""记得""记住""务必""注意""小心""当心"这些词时（"千万不要""千万记得"）是"务必"的意思，也不算数；按整个词判断，所以"千万记录""千万务工人员""千万级"里的"千万"仍算 10000000；
- **改写编了技能**：要点和简介里用[技能词表](jd-parse.md#技能词表)读得出的技能，必须在档案 `skills[]` 里，或者出现在所引条目的原文中；
- 单条要点或简介超过 300 字。

**警告**（不影响退出码，只在没有错误时给出）：档案在材料写好之后改过；档案里熟练（`proficient`）或精通（`expert`）的技能没有列；`job_id` 对应的岗位要求某项技能，档案里有，材料没有列。

## 5. 渲染成简历

`resume build`（[resume-pdf.md](resume-pdf.md#从材料生成resume-build)）先检查材料，再按 `ref` 从档案取出姓名、学校、日期等，和材料里的选择、改写合成一份不含引用的平铺内容（形状同 `jobsearch_cn/resume_templates/sample.json`），交给 Typst 模板和 Word 版。规则（规划者 2026-11-01 裁定）：

| 部分 | 怎么排 |
| --- | --- |
| 抬头 | 姓名；联系方式是电话、邮箱、GitHub、个人网站，有哪项写哪项，用" \| "隔开 |
| 求职意向 | 全从档案拼，材料不带："求职意向："加上意向岗位（招聘类型：实习、校招、社招）、首选城市、每周几天和可实习几个月（只在招聘类型含实习时写）、"YYYY.MM.DD 起可到岗"，用" · "隔开；档案没写的项不写 |
| 个人简介 | 暂不印出：模板没有这一块。`summary` 照样要检查 |
| 教育经历 | 按材料的顺序。左边学校，中间"专业 · 学历"（专科、本科、硕士、博士），右边日期；要点是绩点和排名一条（绩点前加"GPA "，原文已经写了 GPA 或"绩点"的不加），材料列了课程时再加"主修课程："一条 |
| 经历 | 按 `type` 分节：实习经历、工作经历、项目经历、科研经历、竞赛经历、校园经历；各节按材料里第一次出现的顺序，节内按材料的顺序。项目、科研、竞赛左边写 `name`，实习、工作、校园写 `org`，没有时用另一个；中间写 `role`；要点是材料改写后的 |
| 专业技能 | 按档案里的 `level` 分行，依次是精通、熟练、熟悉、项目中使用（`level` 为 null，即只在经历里出现的技能）、了解；行内按材料的顺序，用材料的写法（例如岗位写 Golang，材料也写 Golang） |
| 荣誉与证书 | 奖项写"名称（YYYY.MM）"；证书写"名称 详情"；语言写"名称 水平"，但水平已经出现在列出的某条证书里的不再单列（例如有了"CET-6 552"，就不再写"英语 CET-6 552"） |
| 日期 | `2025.09 - 2027.06`，ASCII 连字符；没有结束日期写"至今"，只有结束日期就只写它 |

材料没列任何条目的那一节不印。
