# 更新记录（CN）

只记录 `jobsearch_cn` 和 CN 文档的版本变化；上游框架的版本见仓库根目录的 `CHANGELOG.md`。过程细节见 [工作记录](worklog.md)。

## v0.2.0（2026-11-05）

第二个版本：个人档案与可解释匹配（M2）。在 v0.1.0 的 JD 入库之上，用本机的个人档案先按硬性条件过滤岗位，再给出可解释的评分和报告。和 v0.1.0 一样，tag 打在当时的 master 上，所以也带有 v0.3、v0.4 的预览功能（见下文）。

**新增**

- 个人档案 [Profile v1](profile.md) 与建档流程 `cn-setup`（[说明](profile-setup.md)）：
  - `profile validate`、`profile show`（默认隐去联系方式）；`profile extract` 把 Word、PDF 简历转成纯文本，交给 Agent 起草档案；
  - 档案记录求职方向和各维度的权重、首选城市和可以接受的城市、期望薪资（可以分档）、愿不愿意去外地面试；
  - 建档时必问能否远程、愿不愿意去其他城市；写了意向城市而这两项留空时，`profile validate` 给出警告。
- 硬性条件过滤 `match filter`：届别、学历、每周天数、实习时长、城市与远程、岗位类型、排除项、面试形式、到岗时间，逐项给出"符合 / 冲突 / 未知 / 不适用"，附 JD 出处和档案字段。判"未知"时写明缺的是哪一方的信息，例如"JD 没写届别；你是 2027 届"。
- 可解释评分 `match score`、`match validate`、`match save`、`match show`、`match list`（[说明](match.md)）：
  - 技能、方向、薪资、地点由规则打分；经历由 Agent 对照 JD 和档案补，规则给不出方向时也由 Agent 补。每个维度都有理由和依据，Agent 引用的 JD 片段和档案条目必须真实存在，否则 `match validate` 不通过；
  - 加权总分、等级（例如"较匹配（good）"）和缺口；记录存在 `<数据目录>/matches/`，岗位、档案、权重或规则版本变了会标为过期；
  - 薪资：日薪和月薪按每周天数互相换算，年薪按 12 个月折算；写了理想薪资和步长时按档给分，包餐和餐补也折算进去；
  - 地点：首选城市、可以接受的城市、其他城市分档给分；
  - 评一批岗位前，Agent 先问你现在最看重什么，换算成权重给你确认；`match list --weights` 可以临时换一组权重试算排序，不改档案和记录。
- 评分报告和反馈表 `match report`：离线 HTML 报告逐项列出过滤结论、各维度的分数和依据、总分的计算过程、待确认的事项和怎么确认；反馈表 `feedback.csv` 用来填你认不认可，Agent 读回后向你汇总。
- 技能词表按方向分组（技术、数据、产品、运营、设计、市场、财务、人力、通用）；同义写法算同一个技能（例如 Go / Golang、PPT / PowerPoint、大模型 / LLM），带版本号的写法（例如 Vue3）算作这个词；"熟悉 Golang 或 Java"记为任选其一，一个都不会才算缺口。
- 评分工作流由 Claude Code（`cn-match` 技能）、Codex（`AGENTS.md`）和 DeepSeek Harness（`.dsh/skills/`）三个入口共用一份说明。

**JD 解析与岗位库的改进**

- BOSS 直聘的粘贴文本：读得出标题、公司和实习月数；一份 JD 写了几个不同的实习时长时留空，不再取较宽松的那个（v0.1.0 的已知限制，H9）。
- 薪资：读"元/月""元/天""元/年"，万、w、k 的单值和区间，"13薪"；包几餐和餐补金额。
- 新字段：面试形式和面试地点、到岗时间（见 [Job Schema](job-schema.md#面试和到岗时间)）；学历"不限"。
- 工作地点和面试、笔试地点分开；两个学历任选其一时取较低的；专业要求里的词不算技能。
- 重新导入同一份 JD 时，按出处的优先级合并（用户 > Agent > 规则），规则读出的值不再覆盖 Agent 和用户补的值（v0.1.0 的已知限制，H10）；误读的列表可以明确清空。

**安全与隐私**（来自发版前的安全审查 V18）

- 写入前核对真实路径仍在数据目录内，越界的链接（junction、symlink）拒绝写入；读 Word 文件时限制大小、节点数和嵌套层数。
- `profile show` 在联系方式的格式不对时也隐藏；反馈表防公式注入覆盖更多写法。

**v0.3、v0.4 预览（已合并，属于后续版本，还在开发，格式可能变）**

- 中文简历（M3）：
  - 简历材料的格式，每一条都要引用档案条目（`material validate`）；
  - `resume build` 生成一页 PDF（Typst，借用 MIT 许可的 habaneraa 模板）和 Word 版，可以带个人简介；
  - 起草加独立审核的双 Agent 工作流和中文审核清单（`review draft`、`review validate`、`review show`，`cn-resume` 技能）；
  - 打招呼语、投递邮件、内推请求按方向套模板（`material template`、`material render`），只生成文字，不代发。
  - 用户的真实验收（M3-5）还没做。
- 投递记录（M4-1）：`application` 命令组和 `cn-application` 技能，记录投递、状态、回复、跟进和备份，存在本机的 SQLite 里；每次写入先预览，你确认后才写。

**M2-5 第二轮验收（2026-11-04）与修复**

- 第二轮：用户补上期望薪资等档案项，用新的报告和反馈表逐个岗位确认，5 个真实岗位的结论都认可（5/5）；notes.md 的"优势和代表性成果"一节也确认了。真实档案、岗位和匹配记录只在本机 `data/`。
- 第二轮发现的问题都已修复（2026-11-05 合并），包含在本版本里：
  - 档案没写理想薪资和步长（不分档）时，JD 的薪资单位和你的最低期望不同（例如按天和按月）也先换算再比较；原来记 null，要你把最低期望手算成 JD 的单位（PR #138）；
  - 技能词表补上 Maven、Gradle、HTTP、TCP/IP、TCP、UDP、计算机网络、数据结构，网址里的 http 不算技能（PR #138）；
  - 新开关 `availability.remote_unstated_as_conflict`，默认关闭：打开后，你不考虑异地、岗位又在意向城市以外、JD 没写能否远程时，地点判冲突，原来判未知（PR #138）；
  - 经历的提示也按经历的名称、身份和描述找用过的技能；建档时把技能关联到用过它的经历；只改其中几项权重时，其余几项怎么分摊写清楚了（PR #139）。
- 10 份脱敏 JD × 2 份示例档案的过滤和评分结果写成期望表，重复运行结果一致；和人工排序（V5）的对照、各批留出样例的回归测试都通过。

**已知问题**

- 第二轮验收用的 5 个岗位都不在用户的目标城市：地点分都是 0、薪资分都一样，权重怎么调都拉不开差距。"5/5 认可"说明结论讲得通，但对评分区分度的参考价值有限，要用目标城市的岗位再看。
- 岗位还要用户自己找来、粘贴进来；让工具自己找岗位（M6 岗位发现）正在做。
- 规则只认固定词表，经历维度要 Agent 补；按小时计的薪资不换算，JD 和档案都没写每周几天时，薪资也记 null。
- 规则版本（`rules_version`）现在是 11。版本不同的匹配记录会标为过期，要重新评分，Agent 补的经历也要重补。
- DeepSeek Harness 的入口已经加上，还没有在 dsh 上实测（A3）。
- 需要 Python 3.10 及以上；生成简历 PDF 另要 Typst 0.13 及以上（[安装说明](resume-pdf.md)）。

## v0.1.0（2026-10-28）

首个版本：中文 JD 离线入库。按用户决定，tag 打在通过真实 JD 验收的那一版代码上，所以已经带有 v0.2 的预览功能（见下文）。

**新增**

- `jd validate`：按 [Job Schema v1](job-schema.md) 校验岗位记录；每个从 JD 读出的值都必须注明出处，出处片段必须真实出现在原文中。
- `jd parse`：按规则从中文 JD 抽取薪资、届别、每周天数、实习时长、学历、转正、远程、城市、岗位类型、标题、公司、日期和技能，读不准的留空（[说明](jd-parse.md)）。
  - 一次导入多份 JD（一行 `===` 分隔）；
  - 支持 UTF-8、UTF-16 BOM、GBK 输入；拒绝被 PowerShell 5.1 管道损坏的文本；
  - 防注入检查：复用上游 `posting_guard`，补充中文注入句式（G1），只警告不拦截。
- 本地岗位库：`jd save`、`jd list`、`jd show`、`jd status`，`jd parse --save`；按内容指纹和规范化链接去重（G2），重复导入逐字段合并。
- Agent 入口：Codex（`AGENTS.md`）和 Claude Code（`cn-jd-import` 技能）共用 [JD 导入工作流](jd-import.md)。

**v0.2 预览（还在开发，格式可能变）**

- 个人档案 Profile v1 与建档流程 `cn-setup`：`profile validate`、`profile show`（默认隐去联系方式）。
- 硬性条件过滤 `match filter`：逐项给出"符合 / 冲突 / 未知"，附 JD 出处。
- 技能词表移到 `jobsearch_cn/skills.json`，按求职方向分组；用户可以在 `data/config/skills.json` 追加词条。

**修复与验收（2026-10-28）**

- 修复：工作地址里重复出现同一城市时，`jd parse` 会因为列表里有重复项而中止。现在按首次出现的顺序去重，保留原文出处。
- Codex 的样例实测通过；5 份用户提供的真实 JD 的导入、查询、去重验收也通过。用户用真实简历走完了 `cn-setup`，档案确认后保存，通过校验。真实材料只保存在本机 `data/`。

**已知限制**

- 规则是保守的，城市和技能只认固定词表，很多字段需要 Agent 或用户补全。
- BOSS 直聘的粘贴文本：开头有链接、日期这类元数据行时读不出标题；标签行里的公司和单独的"N个月"读不出来；一份 JD 写了几个不同的实习时长时，可能读到较宽松的那个。以上都要 Agent 按原文补全（H9）。
- 重新导入同一份 JD 时，规则读出的值会覆盖 Agent 补全的值，导入后要再核对一遍（H10）。
- 只用 JSON 文件存储，SQLite 按需接入（见[总体规划](master-plan.md) D4）。
- 需要 Python 3.10 及以上。
