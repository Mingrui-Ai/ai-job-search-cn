## 4. 作者邮箱（需要用户确认）

- 作者邮箱 `mingrui.ai@outlook.com` 会随提交公开。我们的 169 个提交都以它作为作者邮箱：其中 126 个的提交者也是它，另外 43 个是在 GitHub 上合并 PR 产生的，提交者是 GitHub。tag `v0.1.0` 的注释里也有它。仓库公开后，任何人都能在 `git log` 或 GitHub 的提交页面看到。
- 作者名有两种写法（本机 git 的用户名和 GitHub 的显示名），都对应 GitHub 账号，本来就是公开的。
- **以后的提交**：用户可以在 GitHub 的 Settings → Emails 打开 "Keep my email address private"，只对以后的提交生效。
  - 打开后，在 GitHub 上合并 PR 等操作产生的提交会自动改用 noreply 地址。
  - 本机命令行提交还要把 git 的 `user.email` 改成同一页面显示的 noreply 地址（`<ID>+Mingrui-Ai@users.noreply.github.com`），否则仍会带上原来的邮箱。本机的 `user.email` 设在全局配置里，改一次，所有工作树都生效。
  - 同一页面的 "Block command line pushes that expose my email" 要等所有会话都改用 noreply 地址之后再打开，否则它们的推送会被拒绝。
- **已有的提交**：改写历史也去不掉这个邮箱。GitHub 给每个 PR 保留的 `refs/pull/*` 引用是只读的，旧提交会一直留在 PR 里，只能请 GitHub Support 清理。如果一定不能公开这个邮箱，唯一可行的是另建一个干净的仓库，也就是 D2 原来的方案。
- 审查者的建议：接受公开（这个邮箱和 GitHub 账号名本来就对得上），以后的提交改用 noreply 地址。
