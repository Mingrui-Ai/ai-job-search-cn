- **resume build 的 OSError**（`resume_pdf.render`、`cli.cmd_resume_build`）：五处可能写失败的地方都改成标准错误输出 `{"error": …}`、退出码 1，不出 traceback：

  - Word 版、说明文件：`cannot write resume-<n>.docx: <原因>`，`.build.json` 同样；
  - 数据目录下建 `resumes/<岗位id>`：`cannot make the folder resumes/<岗位id> in the data directory: <原因>`。

**决策**

- 退出码用 1：同一条命令里 Typst 找不到、PDF 放不进一页（`ResumeError`）都是 1，写不了文件也属于"这次没生成出来"；2 留给"输入读不了"。文件夹是链接、跑出数据目录这类拒绝照旧走 `InputError`（2），不变。
- 错误里只写文件名（`resume-2.pdf`）或数据目录下的相对位置，不写绝对路径：数据目录在用户目录下，绝对路径带本机用户名。
- 保留 `WinError 5` 的编号：`resume-workflow.md` 第 2 节按这个编号告诉用户怎么办；编号不含路径。
- PDF 已写出、Word 版写失败时，不写说明文件（和失败时一样不覆盖原来那份）。旧说明文件的 `material_hash` 或文件摘要对不上新 PDF，审核者第 2 步核对时会发现，所以不另做回滚。
- #132 P3-1 选改说明：`review draft` 的输出是审核结果的初稿（`material_hash`、`coverage`、`style`），加 `warnings` 是改输出格式，要动 `review-format.md` 第 3 节和三个入口的说明；审核者本来就先跑 `material validate`（`resume-workflow.md` 第 2、5 节），那里已经给出这条警告和现在的值。Codex B 也写了"不要求增加 review draft 的警告输出"。改说明是零代码改动，命令行为不变；加一项测试把"`review draft` 不输出警告、`material validate` 输出"固定下来，说明以后再写宽会和测试对不上。
- 没打开 `tests/test_cn_messages.py`（网关提醒）；沟通草稿的 `review draft` 走同一段代码，测试只用简历。
