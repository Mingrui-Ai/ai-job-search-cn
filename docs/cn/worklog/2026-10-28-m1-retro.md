**真实数据暴露的问题**（规划者在本机只读核对，只看汇总，不看具体内容）

- 字段由谁读出（5 份）：

  | 读出方式 | 字段 |
  | --- | --- |
  | 全部由规则读出 | 城市、薪资、每周天数、技能 |
  | 全部靠 Agent 补 | 标题、公司、实习月数 |
  | 规则和 Agent 都有 | 岗位类型、学历各 3 份规则、2 份 Agent |
  | 原文都没写 | 远程、转正、发布日期、截止日期 |

- 原因：4 份文本的开头加了链接和采集日期两行，所以"第一行是标题"的规则落空；公司和月数在"公司｜城市｜薪资｜天/周｜月数｜学历"这种标签行里，规则不认。另外 1 份是整页复制，标题和薪资挤在同一行。转为 **H9**。
- 一份 JD 同时有平台介绍的"3个月及以上"和岗位要求的"连续实习4个月以上"，规则取了前一个。H9 改成：出现几个不同的值时留空，交给 Agent。
- 重新导入同一份 JD 时，规则读出的值会覆盖 Agent 校正过的值。转为 **H10**，优先级改为：用户 > Agent > 规则。
- 用真实档案跑硬性过滤，5 份都是"待确认"：
  - 地点 5 份都是未知：意向城市和岗位城市不同，档案又没写能否远程、是否愿意去其他城市；
  - 届别有 4 份未知：JD 本身没写。

  建档流程要求必须问到远程和异地这两项，`profile validate` 也要提示，这两点并入 **M2-4a**。
- 建档时 Agent 在 `data/profile/` 下留了辅助脚本和草稿。只在本机，不影响结果，但流程应该规定草稿放在 `data/profile/drafts/`、确认后删除，这一点也并入 M2-4a。
- 有一次 Codex 会话试过用用户已登录的浏览器读 BOSS 页面，因为空白页、超时等问题没有成功，最后改用用户提供的文本文件。站内辅助（D5）还没有定，平台也可能限制账号，所以在 D5 决定之前，不用已登录的账号自动读取页面。
