## 决策

1. **默认每周 5 天只用于不分档**（意见书-008 第 4 条问的就是不分档；规划者的派活也写的是"不分档薪资折算时"）。不分档、单位不同、要按天换算，而 JD 没写每周几天、档案的 `target.salary_days_per_week` 也是 null 时，按每周 5 天折算，理由写"按默认每周 5 天、一年 52 周"。JD 写了的先用 JD 的，档案写了的再用档案的，顺序不变。分档的照旧：两边都没写时不换算，记 null，报告提示补 `salary_days_per_week`。
2. **`rules_version` 11 → 12**：同一岗位和档案，薪资维度从 null 变成 0 或 100，缺口也可能多一条薪资。
3. **搜索关键词放在 `target.search_keywords`**：字符串列表，可以不写（不写和 `[]` 一样，`profile validate` 不提示），写了就按 `target.roles` 的规矩查：每一项是非空字符串，不重复（大小写、全半角折叠后比较）。不写 null：列表字段在档案里一律用 `[]` 表示没有。
4. **搜索关键词不进档案摘要**（`score.profile_hash`），和 M2-6d 的权重同理：过滤、评分、简历材料都不读它，只改关键词不应该让已保存的匹配记录和简历材料变成"档案已改"。没写这个键的档案，摘要和以前完全一样，所以不会让旧记录过期一次。
5. 本 PR 只加字段和文档，采集器不读它（规划者派活）。
