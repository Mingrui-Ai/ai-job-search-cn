# 2026-11-04 JD 解析漏提"日薪：180-240 元"（PR #129 验收报告 P2-01）

## 问题

M3 流程验收（`docs/cn/worklog/2026-11-04-m3-flow-acceptance.md` 的 P2-01）：公开夹具 JD 写"日薪：180-240 元"，`jd parse` 的薪资为空。

## 原因

`jobsearch_cn/jd_parser.py` 里"标签 + 不带 k/万 的金额 + 元"的两条规则（`日薪|每天|每日 … 元`、`月薪 … 元`）只允许标签后有空白，不允许冒号或"为"。带 k/万 的月薪、年薪规则早就允许 `[:：为]`，这两条漏了。"元"结尾和区间本身没问题："日薪200元"能读。"180-240 元/天"这种带"/天"的写法本来就由另一条规则读出，不受影响。时薪只有"元/小时"的写法，没有"时薪 … 元"的标签写法。

## 改动

- 日薪/每天/每日、月薪两条规则：标签后允许全角、半角冒号或"为"（和 k/万 规则一致）。
- 补一条"时薪 … 元"规则（同样允许冒号），和日薪、月薪对齐。
- 边界不变：金额后仍必须有"元"（或别的规则认的"/天""/小时"等），"日薪：200"这种裸数字照旧不读。
- 测试：`tests/test_cn_jd_parser.py` 加原文写法和同类写法（全角/半角冒号、为、"元""元/天"、区间与单值、时薪、月薪），以及两条不读的用例。
- `docs/cn/jd-parse.md` 的 salary 行补写法和不读的写法。

## RULES_VERSION

不改。只改了解析，过滤和评分对同一条岗位记录的结果不变；重新导入改变了记录时，匹配记录按 `job_hash` 标为过期（和 H20 同样的处理）。
