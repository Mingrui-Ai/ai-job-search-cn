## 设计稿（待规划者确认）

### 1. 三种材料沿用 Material v1

[material.md](../material.md) 已经预留了"打招呼语、邮件以后沿用同一格式，另加种类"。所以本项不另起格式，加三个 `kind`：

| kind | 用途 | 文件 |
| --- | --- | --- |
| `greeting` | BOSS 直聘等平台的打招呼语 | `data/materials/<岗位id>/greeting-<n>.json` |
| `email` | 投递邮件（标题和正文） | `data/materials/<岗位id>/email-<n>.json` |
| `referral` | 请学长学姐、朋友内推的消息 | `data/materials/<岗位id>/referral-<n>.json` |

公共字段和简历相同：`schema_version`、`kind`、`job_id`、`profile_hash`、`created`。另外三个字段：

```json
{
  "schema_version": 1, "kind": "greeting", "job_id": "job_000000000001",
  "profile_hash": "…", "created": "2026-11-01T10:00:00+08:00",
  "direction": "tech",
  "template": "tech/greeting@1",
  "subject": null,
  "segments": [
    {"slot": "opening", "text": "您好，我是{edu-1.school}{edu-1.major}专业的学生，想应聘贵司的{job.title}。", "refs": ["edu-1", "job"]},
    {"slot": "evidence", "text": "实习期间用 Go 重构订单查询接口，P99 延迟从 120ms 降到 45ms。", "refs": ["exp-1"]},
    {"slot": "availability", "text": "可以{availability.start_date}到岗，每周{availability.days_per_week}天。", "refs": ["availability"]},
    {"slot": "closing", "text": "期待和您进一步沟通。", "refs": []}
  ]
}
```

- `segments[]` 按模板规定的槽位顺序排，每段一个 `slot`、`text`、`refs`。只有 `email` 有 `subject`（结构同一段），其他两种写 `null`。
- `{…}` 是占位符，渲染（`material render` 或另加的 `message render`）时从档案或岗位里取值。能取的值是一个白名单：
  - `job.title`、`job.company`
  - `edu-<id>.school`、`.major`、`.level`
  - `exp-<id>.name`、`.org`、`.role`
  - `availability.start_date`、`.days_per_week`、`.months`
  - `contact.name`

  `contact.phone` 和 `contact.email` 只允许出现在 `email` 的签名段。姓名、学校、公司名都走占位符，材料里不手写。所以和简历一样，这些内容在材料里没有编造的地方。
- `refs` 的规则同 M3-1：每段的引用都要能在档案里找到；另外 `job` 表示引用岗位。段里用到的占位符，它所属的条目必须在本段的 `refs` 里。
- 编了数字、编了技能的检查照搬 M3-1，对照的是所引条目的原文。`job` 的原文是岗位的标题、公司名和技能要求。这样"贵司要求的 Go"这类写法可以，"贵司 2000 人的团队"这类原文里没有的数字不通过。

### 2. 模板放哪、长什么样

模板放在 `jobsearch_cn/message_templates/<方向>.json`，作为包数据，随代码发布，不联网。用户可以在 `<数据目录>/templates/messages/<方向>.json` 放同名文件覆盖，或者新增方向，和自定义词表的做法一样。

一个方向一个文件，三种材料各一节：

```json
{
  "version": 1, "direction": "tech", "label": "技术",
  "greeting": {
    "max_chars": 150,
    "slots": [
      {"slot": "opening", "required": true, "hint": "学校、专业、应聘的岗位"},
      {"slot": "evidence", "required": true, "max": 2, "prefer": ["internship", "project", "research"], "hint": "和 JD 技能最相关的一两条经历，带结果数字"},
      {"slot": "availability", "required": false, "hint": "到岗时间、每周天数（实习岗）"},
      {"slot": "closing", "required": true}
    ],
    "examples": ["您好，我是{edu-1.school}…"]
  },
  "email": {"subject_pattern": "应聘{job.title}-{contact.name}-{edu-1.school}", "max_chars": 600, "slots": […]},
  "referral": {"max_chars": 300, "slots": […]}
}
```

- 模板不是填空题。它规定槽位、顺序、每个槽位优先引用哪类经历、写什么，以及长度上限；正文由 Agent 按 JD 起草，再用 `material validate` 检查。`examples` 是虚构的写法示范，不会被直接拷进材料。
- 各方向的差别主要在 `evidence` 槽位优先引用哪类经历，以及 `hint` 怎么写：
  - `tech`：项目、实习，写技术栈和性能或规模的数字；
  - `data`：分析或建模项目，写数据量和结论；
  - `product`：用户需求、上线的功能和产品指标；
  - `ops`、`market`：活动、内容、增长数字，可以带作品链接（`exp.url`，如果有）；
  - `design`：作品集链接，必须放；
  - `finance`、`hr`：证书、实习单位和职责。
- 第一版先写 `tech`、`data`、`product`、`ops` 四个方向，外加兜底的 `default`。其余方向先用 `default`，以后按需补，补一个方向只加一个文件（总体规划"新增方向只加配置"）。

### 3. 按方向怎么选

新命令 `material template <岗位id> --kind greeting|email|referral [--direction X]` 输出要用的模板和选它的理由（JSON），给 Agent 起草用。选法按顺序：

1. 给了 `--direction` 就用它；
2. 否则用评分里同一个函数 `score.direction_skills`，看 JD 技能主要属于哪些方向，取其中也在档案 `target.directions` 里的那一个（有并列时按档案里的顺序）；
3. 没有交集时，取档案 `target.directions` 的第一个；
4. 还是没有，或者这个方向没有模板文件，就用 `default`。

材料里记下用了哪个方向和模板（`direction`、`template`）。模板版本变了，`material validate` 给警告，不报错。

### 4. 长度上限

按字符数算，占位符按代入后的长度：渲染前不知道值有多长，所以检查时就从档案和岗位里代入再数。

| kind | 上限 | 依据 |
| --- | --- | --- |
| `greeting` | 150 字 | 平台招呼语一屏能看完；BOSS 自定义招呼语的输入框本身也有上限 |
| `email` 标题 | 40 字 | 邮箱列表里不被截断 |
| `email` 正文 | 600 字 | 约一屏；简历作为附件 |
| `referral` | 300 字 | 微信消息一屏 |

上限写在模板里，用户覆盖文件可以改小，不能改大：代码里有硬上限，就是上表的值。

### 5. 禁用说法

词表放在 `jobsearch_cn/message_templates/banned.json`，用户可以追加，不能删。分三级：

- **不通过**（错误）：
  - 没有代入的占位符和模板标记（`{xxx}` 不在白名单里、`【填写】`、`XXX`）；
  - 敏感个人信息：身份证、年龄、出生、婚育、籍贯、民族、政治面貌、健康这些词；
  - 联系方式写在 `email` 签名段以外，或者正文里手写了手机号、邮箱（用正则查）；
  - 没有依据的承诺：写了到岗时间、每周天数、实习月数，但 `refs` 里没有 `availability`，或者和档案的值不一致；
  - 最高级和绝对化的自夸："精通一切""最强""顶尖""第一""100%""完美""无可挑剔"。原文里有的词放行，例如奖项名里的"第一名"。
- **警告**：
  - 套话："在吗""亲""急求""求带""万分感谢""麻烦您了"连用好几次；
  - 降低自己的话："虽然我能力不足""可能不太合适"；
  - `referral` 里提到薪资；
  - `greeting` 里放链接（平台常常会屏蔽）。
- 判断时按整个词匹配，不按单个字。规则写成数据，不写死在代码里，便于以后改。

### 6. 检查命令

`material validate` 按 `kind` 分派，`resume` 的行为不变。新种类不通过的条件：

- 字段缺失、多余或类型不对；
- 槽位不在模板里、顺序不对，或者缺了必需的槽位；
- 引用找不到，或者用了占位符却没在 `refs` 里引用它所属的条目；
- 编了数字或技能；
- 超出长度上限；
- 用了禁用说法。

输出格式、退出码和 M3-1 一致。

- 选模板的用例覆盖：给了 `--direction`、JD 和档案方向有交集、没有交集、方向没有模板文件。

### 8. 不在本项做的

- 不自动发送：只生成文字，用户自己复制或发送。
- 渲染（代入占位符后输出纯文本，以及邮件附带简历）：本项先实现代入，`message render` 输出纯文本给用户复制；发邮件不做。
