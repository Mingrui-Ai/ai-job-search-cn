**决策**

- 维度在上游 `04-job-evaluation.md` 的基础上，按学生找实习和校招的情况调整：
  - 去掉文化匹配：本地档案没有这方面的数据，以后有公司调研再考虑；
  - 地点并进硬性过滤；
  - 剩下技能、方向、经历、薪资四个维度。
- 默认权重为技能 35、方向 30、经历 25、薪资 10，档案可以改。
- 技能、薪资和规则能算出的方向由代码算，Agent 不能改。经历，以及规则判断不了的方向，由 Agent 补，必须引用 JD 原文和档案 id。`match validate` 会重新算总分和等级，Agent 不能直接改总分。
- 方向复用词表分组：档案用分组键（`target.directions`）表示想做的方向。用户自己加的分组也能直接使用，方向不写死。
- 薪资只比较单位相同的情况，不做日薪、月薪换算，避免猜测。
- V2 指出的问题这样处理：
  - "不适用"：硬性条件新增 `not_applicable`；
  - "明确不要求"：学历新增取值 `none`；
  - 同义词：词表新增 `same_as`，只在比较时生效，解析结果仍保留原文写法，出处校验不受影响。
- 契约补充会让 V2 的两处人工期望对不上（学历变为 `none`，校招的天数和时长变为不适用），提前认定为允许的例外。
- 匹配记录用 JSON 文件（D4），通过摘要标出岗位或档案改动后已过期的记录。
