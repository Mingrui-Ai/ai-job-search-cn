# 2026-10-30 M3-1 材料格式与 `material validate`（Claude C）

规划者按经理意见书-003 把 M3-1 提前，和 M2-5 第二轮并行。先写格式设计，规划者看过再写代码。

## 现状：档案条目有没有稳定的 id

- `experience[]` 已有 `id`（`exp-1`、`proj-1`，小写字母、数字和连字符，最长 40，不重复），`skills[].used_in` 引用它，`profile validate` 已查存在和重复。
- `skills[]` 没有 id，但 `name` 不重复（`check.unique_names`），可以直接用名字引用。
- `education[]`、`awards[]`、`certificates[]`、`languages[]` 没有 id，也没有不重复的名字。只能按下标引用，而下标在建档时插入一条就会变，不稳定。
- 经历的 `bullets` 是字符串列表，单条没有 id。

## 设计（草稿）

### 1. 补 id

- `education[]`、`awards[]`、`certificates[]`、`languages[]` 各加可选的 `id`，规则同 `experience`（同一个正则），**整份档案里不重复**（跨表也不重复，引用时不用写是哪一表）。建议前缀 `edu-`、`award-`、`cert-`、`lang-`，只是约定，不强制。
- 旧档案：没有 `id` 的条目照样合法，只是不能被材料引用；`material validate` 遇到引用不到的就报"这一条在档案里没有 id，先运行 cn-setup 补上"。`profile validate` 加一条警告（不是错误），列出没有 id 的条目。
- 写入：cn-setup 新建和更新档案时给每条写上 id；已有的 id 不改，删掉的不复用。`profile.md` 和 `profile-setup.md` 写明。
- schema：`PROFILE_VERSION` 不升。id 可选、旧档案仍合法，不需要迁移命令；需要引用时由 cn-setup 补。规划者若希望强制，可以改成必填并升版本，再加 `profile migrate`，见末尾问题 1。
- 经历的单条 bullet 不加 id：材料按经历 id 引用，改写后的文字由下面第 3 节的检查兜底。

### 2. 材料文件

放在 `data/materials/<job_id>/resume-<n>.json`（`data/` 已被 `.gitignore` 忽略，不提交；写入沿用 H25b 的数据根检查）。一份简历一个文件，例子（虚构）：

```json
{
  "schema_version": 1,
  "kind": "resume",
  "job_id": "j-20261030-xxxx",
  "profile_hash": "…",
  "created": "2026-10-30T20:00:00+08:00",
  "summary": {"text": "两段后端实习，熟悉 Go 和 Python 的检索服务", "refs": ["exp-1", "proj-1"]},
  "education": [{"ref": "edu-1", "courses": ["机器学习", "分布式系统"]}],
  "experience": [
    {"ref": "exp-1", "bullets": [
      {"text": "用 Go 重构订单查询接口，P99 延迟从 120ms 降到 45ms", "refs": ["exp-1"]}
    ]}
  ],
  "skills": ["Go", "Python", "MySQL"],
  "awards": [{"ref": "award-1"}],
  "certificates": [{"ref": "cert-1"}]
}
```

- 姓名、联系方式、学校、公司、职位、日期**不写在材料里**，渲染时按 `ref` 从档案取，材料里没有可编造的地方。
- 材料只决定：选哪些条目、排什么顺序、经历的 bullet 怎么改写、技能列哪些、教育列哪几门课。
- `profile_hash` 记生成时的档案摘要（沿用 `score.profile_hash`），档案改了以后 `material validate` 给警告"档案在材料生成之后改过"。

### 3. 引用规则和检查项（`material validate`）

不通过（错误）：
- 字段、类型、未知字段，同 `profile validate` 的写法（`<字段路径>: <原因>`）；
- 每个 `ref` / `refs` 在档案里存在；`experience[].bullets[].refs` 至少一条，且包含所在经历的 `ref`；`summary.refs` 至少一条；
- `skills[]` 每项是档案 `skills[].name` 里有的；`education[].courses` 每门是该条教育的 `courses` 里有的；
- bullet 里的**数字**（含百分号、单位前的数）都要在所引条目的原文（bullets、name、role）里出现过，防止改写时编数字；
- bullet 和 summary 里用词表读得出的**技能**，都要在档案 `skills[]` 里，或者在所引经历的原文里；
- 同一条目不重复列出；单条 bullet 不超过 `MAX_BULLET`。

警告（不影响退出码）：档案在材料之后改过；档案里有 `proficient` 以上的技能没列；JD 要求的技能档案里有、材料里没列（读取 `job_id` 对应的岗位，读不到就跳过这一项）。

输出和其他校验子命令一致：标准输出 `{"valid": …, "errors": […], "warnings": […]}`，有错误时退出码 1，输入读不了（文件不存在、不是 JSON）时按 `InputError` 退出码 2。命令：`python -m jobsearch_cn material validate <文件>`，档案路径和数据目录参数同 `profile validate`。

### 4. 怎么转成 M3-2 的渲染内容

另加一步 `material render`（M3-2 第二部分做）：按 `ref` 从档案取出姓名、学校、日期等，和材料里的选择、改写合成一份**不含引用的平铺 JSON**，字段和 Claude B 在 M3-2 第一部分里给模板用的固定虚构内容相同；Typst 用 `json()` 读它，Word 版由同一份 JSON 生成。所以 M3-2 第一部分定下的渲染字段就是两边的接口，我这边跟着它的字段名写转换。

### 5. 测试和文档

- 示例档案 `tests/fixtures/cn/profile/tech` 补上 education、awards、certificates、languages 的 id，加一份示例材料；通过的一份，不通过的逐项各一份（引用不存在、编数字、列了档案没有的技能、引用了没有 id 的条目等）。
- 格式写进新文档 `docs/cn/material.md`，`profile.md` 加 id 的说明。
- 不改 M2 的评分和解析；`profile_hash` 会因为示例档案加 id 而变，只影响测试里的固定值，逐项核对。
