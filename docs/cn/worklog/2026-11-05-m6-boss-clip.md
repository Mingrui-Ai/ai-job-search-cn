# 2026-11-05 M6 BOSS 一键收藏插件（boss-clip）

经理意见书 009 第 2 条 A。执行者 B（cn-b），分支 `feat/cn-m6-boss-clip`（基于 origin/master）。

## 背景

BOSS 对程序控制的标签页给空白页（规划者 11-05 实测），不做反检测。改成经理平常浏览时点插件按钮，存下眼前这一页，之后 `jd screen` 照常过滤评分。

## 决定

- **形态**：Manifest V3 未打包插件，`extensions/boss-clip/`（manifest.json、background.js、clip.js），自写代码，MIT。
- **权限**：`activeTab` + `scripting` + `downloads`，没有 `host_permissions`、`content_scripts`、`<all_urls>`、`debugger`。更小的组合不行：没有 `scripting` 就没法在点击时读 DOM（不常驻页面就只能这样），没有 `downloads` 就没法写文件。测试里固定了这三项，并检查脚本里没有 fetch、打开/跳转标签页、点击、滚动。
- **读页面**：点击时用 `chrome.scripting.executeScript` 放进 clip.js，读一次 DOM 返回结果。页面本身不改：要去掉的部分（招聘者、在线状态、相似职位等）在读字段时跳过，字段里含有这些部分时读它的副本。
- **选择器**：照抄 PR #142 `boss.py` 的 `SELECTORS`（同样的去除列表、关闭判断、验证码和登录判断）；列表卡片多读了标签和公司（`card_tags`、`card_company`），是猜的，未核对真实页面，文档里写明了。
- **列表页**：存所有已加载的卡片（DOM 里有的），不滚动。一张卡片一个文件，`text` 是摘要，`extra.page = "list"`。以后存详情时按 `site_job_id` 去重、原文替换。
- **保存与搬运（经理操作最少的方案）**：插件只能写下载目录，存到 `<下载目录>/jobsearch-boss-clip/<点击时间>-<ID>.json`，`saveAs: false`。新命令 `jd inbox-import [文件夹]`（默认 `~/Downloads/jobsearch-boss-clip`）把格式正确的文件（`screen.read_item`，与 `jd screen` 同一套检查）搬进新批次 `data/inbox/boss/<YYYYMMDD-HHMMSS>/`，输出里给出下一步的 `jd screen` 命令。经理只需要点按钮，筛的时候对 Agent 说一句；Agent 连着跑两条命令。
  - 没选"`jd screen` 直接读下载文件夹"：那样文件一直留在下载目录，每次都重读全部旧文件，而且批次目录的来源要靠 `--site`；搬进批次后，收件夹里留有每批的原件，和采集程序一致。
  - 文件名带毫秒时间，按名字排序 = 点击顺序。
- **离线测试**：`tests/test_cn_boss_clip.py`。clip.js 在 node 下用一个极小的假 DOM（`extensions/boss-clip/test/fixture_pages.js`，按选择器名字匹配，不是 CSS 引擎）跑虚构的详情页、列表页和几种拒绝的页面，输出再交给 `screen.read_item` 和 `jd_parser` 检查。没有 node 时这一组跳过（CI 的 ubuntu 自带 node）。inbox-import 用临时目录测搬运、留下的文件、同一秒两个批次、命令退出码。
- **文档**：PR #142 还没合并，`docs/cn/collect.md` 只在那个分支上；为了不和它冲突，安装步骤写在新文件 `docs/cn/boss-clip.md`，README 文档表加了一行。#142 合并后可以在 collect.md 里加一句链接（交规划者定）。

## 审核返工（Codex B 首审三项 P2）

- **`next` 丢数据目录**：`jd inbox-import --data-dir X` 给的 `jd screen` 命令没带目录，岗位写进了默认目录。现在 `next` 总是带 `--data-dir`（实际生效的目录，来自环境变量时也写上），两个路径都转成绝对路径。Windows 用双引号（cmd、PowerShell、Git Bash 都认），路径结尾的反斜杠（盘符根目录）加倍，否则会把结尾的引号转义；其他系统用 `shlex.quote`。
  - 路径里有 `$`、反引号（PowerShell、Bash）或 `%`（cmd）时，双引号挡不住 shell 展开。批次路径就在数据目录下面，展开后批次对不上，命令报错退出，什么也不写（`$` 在 PowerShell 下实测：两个目录都没有岗位）。这种路径手动改写引号即可，没有再做一套按 shell 区分的写法。
- **登录弹窗盖在旧岗位上**：`pageProblem` 先看岗位内容再看登录，弹窗被跳过。选择器拆成 `login_wall`（弹窗、登录表单，优先判断）和 `login_link`（页头链接，只在页面没有岗位内容时算没登录）。`login_wall` 只算用户看得见的：页面可能一直留着隐藏的弹窗节点，所以用 `checkVisibility` 加尺寸判断。判断只看选择器，不看文字，JD 里写"登录""验证码"不受影响。
- **空标题骨架页**：`职位描述` 是无条件写入的，空 h1 也能通过 `read_item`，再由 `jd screen` 替换已保存岗位的标题和原文。现在先读去掉非岗位区块后的标题文本，没有字母或数字（空、空白、零宽字符、纯标点）就报错、不生成条目。
- **验证**：新增回归测试见 `tests/test_cn_boss_clip.py`（`next` 按打印出来的样子交给 cmd/sh 和 PowerShell 实际运行）；11 个变异（去掉 `--data-dir`、不加引号、隐藏弹窗也算、标题只看节点等）都被测试抓到。本机 headless Chrome 跑了合成 HTML（弹窗/表单 + 标题/卡片、四种隐藏写法、页头链接、JD 词语、空/空白 h1），结果符合预期，网络请求 0，页面未被改动。Git Bash 下 `next` 也实际跑过。

## 规划者 21:03 裁定：有标题无描述的详情

返工时复现：有职位名、没读到描述的详情页也能保存，`jd screen` 后完整岗位只剩标题和"职位描述"。现在 `clipPage` 在生成文本前检查描述：去掉常见标题词和占位词（职位描述、岗位职责、任职要求、加载中、暂无等）后，至少还要有两个文字（中文或英文字母），否则报错、不生成条目。

- 数字和标点不算文字（`1. 2.` 这种空列表不算描述）；"负责整理数据"这样短但有内容的、"岗位职责：写周报"这样带标题的照常保存。
- 这些词表是按"页面还没加载完"的样子写的，没有真实页面证据；真实 JD 不会只有这些词，判错的代价也只是显示 `×`。
- 回归：先存完整岗位，再处理不完整页面，库文件完全不变；之后完整的新版详情照常更新，标题和 id 保留（`test_incomplete_detail_cannot_reach_a_saved_job_and_a_complete_one_still_updates`）。6 个变异都被抓到，本机 headless Chrome 跑了 11 个合成页面。这一步只跑了定向测试，全量在下一节修复后一起跑。

## 规划者裁定：列表摘要不覆盖完整详情

返工时复现：详情存过以后再存同一岗位的卡片，全文被摘要替换。规划者接受最小方案：

- `screen.run()` 里加一个分支：文件的 `extra.page == "list"`、库里已有这个岗位且原文不同时，不写入，算 `unchanged`，`warnings` 写 `summary_kept` 并说明要存详情页才刷新。`store.py`、schema 不动，没有这个标记的文件路径不变。
- **摘要对摘要不更新**（规划者接受）：记录里不知道存的是详情还是摘要，要区分就得改 schema。代价是只存过卡片的岗位，卡片变了仍留旧摘要，直到存一次详情。
- **没放在 `jd inbox-import`**：导入时只能查当时的库，挡不住重跑旧批次和"已导入未筛"的情况。
- **只认正好是 `"list"`**：`extra.page` 也可能是"第几页"的数字（screen.md 的例子）。不带标记的摘要（手写的）不受保护，不猜内容。
- 顺带让卡片+详情的批次重跑时变成 `unchanged`，符合"重跑不改东西"。
- 验证：方案矩阵写进 `tests/test_cn_screen.py` 的 `ListSummary`（同批次和跨批次两种顺序、重跑、无标记、只靠链接找到、状态保留，以及库文件内容和修改时间都不变）；`tests/test_cn_boss_clip.py` 用插件实际输出跑了一遍 `jd screen`。10 个变异都被抓到。

## 遗留

- 审核者列的两项 P3 未改（本轮只修 P2）：`--data-dir` 指向文件时输出 traceback；跨盘移动写入失败时新批次留下残缺文件。
- `blocked`（验证码）选择器仍是节点存在就停，没按可见性判断。隐藏的验证码节点会误停，但不会存错内容；真实页面上是否有这种节点，要和下面的选择器核对一起看。
- 选择器没在真实 BOSS 页面上验过：需要经理装上后点几页，看按钮上的数字和 `jd inbox-import` + `jd screen --check` 的结果。
- "下载前询问保存位置"打开时，Chrome 可能仍弹保存框，文档里写了关掉这一项。
- cn-jd-import 技能里还没写"筛一下我收藏的岗位"这句话该跑哪两条命令；要加的话另开一项（改技能要过 lint_skills）。
