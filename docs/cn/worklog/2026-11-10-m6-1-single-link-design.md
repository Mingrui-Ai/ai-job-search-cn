## 决策

- 首版限既有北森本机白名单和规范 HTTPS 详情 URL；拒绝 CDP，不借用用户浏览器状态。
- 复用完整正文解析、原子不覆盖写入和结构异常诊断；批量搜索的已知岗位跳过语义保持不变。
- robots 一次同源 GET、0 跳转/0 重试；404 按未发布，其他失败不确认；64KB 是接受上限，不是传输流量上限。透明共同身份和保守规则检查不靠换 UA 绕限制；Crawl-delay 超过 9 秒则停。
- 旧 robots 工具含联网重试且包不允许导入它，因此只将所需纯匹配算法迁入 robots_policy；上游工具、UPSTREAM_TOOLS、settings/security_guards 均不动。
- 普通 Tab/open_tab 保持原行为；仅具名 SingleTab/open_single_tab/_single_support 可使用 route/new_context，其他静态禁止项仍覆盖全文件，两个 launch 分别验证为本机 Chrome/headless。此测试变化经规划者单独确认，并有实际导航行为测试。
- 旧版频道只作适配器选择，不注入为正文事实；公司标明白名单来源，未知日期不推断。真实岗位是否有名额不在页面读取结果中推断。

## 独立审核后的路径修复

- 独立审核发现开始前缺少只读路径预检：收件目录位置为普通文件或 junction 时仍先访问网页；创建目录的部分 OSError 会泄漏为异常。另有写入失败时 saved 为 0，但 batch_dir 仍非 null 的输出偏差。
- 仅在 SingleRun 内增加预检，在读取去重记录和启动浏览器前验证现存路径，不调用 mkdir/safe_dir；显式选择的数据根链接仍支持。写入阶段继续使用旧保护，并把 StoreError/OSError 映射为单链接 JSON 停止。未保存时清空 summary.batch_dir，不改变批量输出或 Store 契约。
- 新增普通文件、真实 Windows junction、无法读取元数据、预检后文件/junction 替换、并发同名原件和无写入输出的回归；定向与包边界共 90 项通过（4.111 秒）。
- 初版冻结提交的正式全量为 2096 项、37 跳过，504.541 秒；规划者回报该版本独立本机浏览器最终 26/26 及 118 项证据核对通过。本次只改路径预检/错误汇总，browser/robots_policy/beisen/cli 未改，导航证据由独立验证者按差异绑定到修复提交；修复版正式与独立检查按新 SHA 记录。
