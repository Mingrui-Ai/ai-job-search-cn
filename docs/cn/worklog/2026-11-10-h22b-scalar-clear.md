# 2026-11-10 · H22b 明确纠正旧标量和对象

**完成**

- 新增可选 `evidence.<字段>.clear: true`，允许把 15 个独立 nullable 标量／对象整体纠正为 null。Schema 校验明确意图、非空依据和 Agent 严格逐字引用；存储合并保留清空出处与标记。
- 来源仍为 `user > agent > rule`。低优先级显式清空整条拒绝，已清空值阻止低优先级重导入恢复错误；普通 null、H22 列表及不同原文替换维持原契约。
- 带标记的 `jd save` 只接受一个完整岗位或单条 jobs 包装，多条载荷在写入前拒绝。唯一操作说明写入 `jd-import.md`，Schema 文档记录结构与兼容边界，路线图新增 H22b。
- 新增纯虚构回归，覆盖全部允许字段、出处优先级、清空持久化、无标记兼容、非法输入、单条错误原子性、技能组保护、去重路径、匹配过期和 CLI。

**决策**

- 普通未知值不能表达纠正意图，不改变全局 null 合并；只有显式标记参与清空。用户来源必须来自用户本人，不得将 Agent 判断改标 user。
- Schema v1 增加可选出处键，不迁移历史记录；旧版本工具会拒绝新键，不能通过删除持久标记降级。对象整体清空，不允许容器、子路径、列表、身份或来源等元数据带标记。
- 单条校验和合并错误不部分写入；本项不增加跨文件事务或批量强制清空。岗位摘要自然变化，使旧匹配标为 job 过期，不改评分公式、RULES_VERSION、档案或真实岗位库。
