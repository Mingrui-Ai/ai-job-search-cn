# 2026-10-30 · M3-2a：habaneraa 模板、Typst 工具链、压成一页、PDF 检查（Claude B 会话）

> 状态（2026-10-30 存档）：代码、测试和文档完成，三项检查通过，**PR 还没开**。分支 `feat/cn-m3-2a-template`。范围是 M3-2 的第一部分；Word 版和接 M3-1 的材料格式是第二部分，等 M3-1 合并后做。规划者裁定：加 `resume sample` 命令；这个 PR 不改 ci.yml，CI 装 Typst 另立 H31。

**做了什么**

- 模板：取 habaneraa/typst-resume-one-page 的提交 `98aea62` 的 `src/lib.typ`（MIT，许可文件原样保留），放在 `jobsearch_cn/resume_templates/habaneraa/`。来源和改动写在同目录的 `SOURCE.md`，仓库加 `THIRD_PARTY.md`。
  - 去掉 `@preview/nerd-icons`（LGPL-3.0），联系方式改成纯文本、不加链接。
  - 章节标题包进 `block(sticky: true)`。
- `jobsearch_cn/resume_pdf.py`（只用标准库）：
  - 找 Typst：`--typst` 参数 → 环境变量 `JOBSEARCH_CN_TYPST` → PATH 里的 `typst`，要求至少 0.13；
  - 字体：从 `typst fonts` 里按 Noto → Noto CJK → Source Han → 微软雅黑的顺序选；
  - 编译：在临时目录里放模板副本和 `resume.json`，用空的 package 目录编译，不会联网下载；
  - 压成一页：先试最松的 1.5，不行就在 0.8–1.5 之间二分查找 6 次（最多编译 8 次）；最紧也放不下就报错、不写文件；
  - 检查：先跑 `tools/verify_pdf.py --pages 1 --ascii-dates`；再读字体的 ToUnicode 映射，查康熙部首（U+2E80–U+2FDF）和私用区（三段）；还查 Type 3 字体，以及每个字段都在文本层里（忽略空白）。
- 命令 `python -m jobsearch_cn resume sample [--typst PATH]`：用固定的虚构内容生成 `<数据目录>/resumes/sample.pdf`，再检查。
- 文档 `docs/cn/resume-pdf.md`：Typst 便携版的安装、字体、命令、压页、检查各是怎么回事。

**量过的**

- 标题修复不改版式：样张在 1.5、1.0、0.8 三档间距下，修复前后每段文字的纵坐标完全相同。标题块的 `above`、`below` 是量出来的：不设时，下面每节都上移 5.6 pt（间距 1.0）。
- 页尾标题：在内容长度 × 8 档间距、共 135 次两页编译里，修复后标题都不落在页尾。修复前在实验内容里出现过。`breakable: false` 对结果没有影响，所以没写。
- 压页：实习和项目放大 5 倍时得到 1.051，和 M3-0 的结果一样。看过页面图：一页，标题和条目都完整。
- 映射读出的字符集和 pypdf 读出的完全一致（测试里也比较）。
