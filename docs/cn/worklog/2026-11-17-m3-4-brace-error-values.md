# 2026-11-17 · M3-4 花括号报错不再带出代入的值

## 完成

- 修了主干上的一个既有问题（#175 的独立审核发现）：检查沟通材料（打招呼语、投递邮件、内推请求、跟进正文）时，"代入以后文字里还有花括号"这条报错引用的是**代入后**的文字里花括号前后各约 8 个字符。占位符多写一层花括号时（邮件 `signature` 段写 `电话：{{contact.phone}}`，或 `{contact.email}}`），代入的电话、邮箱正好挨着花括号，被带进 `material validate`、`material render`、`review draft` 的输出：电话带出 8 位，邮箱带出末尾 8 个字符，`{{contact.name}}` 带出姓名，岗位名、学校名带花括号时带出这个值。
- 现在这条报错不再看代入后的文字（`jobsearch_cn/messages.py` 的 `_Checker._braces`）：
  - 手写多出来的花括号（`{ 回复 }`、`{{edu-1.school}}`）：引用材料原文里第一个多余花括号附近的一小段。原文里占位符还是名字，所以引用里只有起草时自己写的字和占位符名。引用的两头碰到占位符时把它补完整，后面紧跟的多余花括号也带上，`{{contact.phone}}` 不会被截成半个。
  - 档案或岗位库里的值本身带花括号：只说是哪个占位符（`in the value of {job.title}`），不显示值，提示去改档案或岗位库里的这个值。
  - 两种情况同时出现时各报一条。
  - 原文里同时有检查认得出的手写联系方式（手机号、邮箱、带"微信""QQ"标签的号码）时，这条报错不引用原文，只说明原因。手写的手机号、邮箱本来就是"不通过且不显示"，花括号这条不能反过来把它显示出来。
- 新增 8 个回归用例（`tests/test_cn_messages.py` 的 `BraceErrors`），数据全部虚构；`docs/cn/material.md` 7.4 同步了这条报错的说明；路线图"待办"记了这一项和另外两条没做的 P3。

## 决策

- **引用原文，不引用位置**。只报"第几个字符有花括号"最安全，但起草的人还得自己数；原文片段一眼能看出是哪里多了一层。原文是材料文件里已有的字，不含代入值。
- **报错开头不变**：仍是 `<段>.text: once filled it still has a brace (`。V23 对照的映射（`tests/fixtures/cn/messages-m3-4-comparison/comparison-mapping.json`）按这句话归类，原有的两处测试断言也认这句话。括号里和后面的提示改了：手写的花括号提示"占位符照 `{entry.field}` 写，不要别的花括号"，值带花括号提示"改档案或岗位库里的值"，不再两句混在一条里。`actual/` 下是各次对照当时的输出记录，没有重跑，也没有改。
- **只在原来报错的时机报**：有占位符取不到值时先报那个错，不报花括号，和原来一样；正确的材料、其他报错、退出码、`material render` 的输出都没变。
- **仍以代入后的文字为准来判断有没有花括号**，原因再从原文和各占位符的值里找。两处来源都找不到（按构造不会发生）时也照样报错，不让带花括号的文字通过。
- **同一条链上其他报错的排查**（`messages.py` 和它直接调用的 `material`、`profile`、`schema` 里的检查，以及 `cli.py` 里输出这些报错的三个命令）：
  - 占位符、引用（`refs`）的报错只引用材料里写的占位符名和条目 id；数字、技能、禁用说法的报错引用的是材料原文（占位符先去掉），所引条目的原文只拿来比对，不显示；长度超限只报字数；`profile_hash` 的警告给的是摘要。这些都不带代入值，没有改。
  - 到岗承诺的报错会显示档案里的到岗日期、每周天数、实习月数（"写 4天 或 {availability.days_per_week}天"）。这是有意的（material.md 7.4：提示写档案的值），不是联系方式，没有改。
  - 手写的微信号、QQ 号的报错会引用命中的那几个字。这是材料里手写的字，不是代入值，行为和文档都保持原样；是否也改成不显示，见"遗留"。

## 遗留

- 手写微信号、QQ 号的报错引用命中的原文（`'微信号：…' - 手写了微信号…`）。#175 给档案加微信号字段以后，材料里手写的微信号更可能是真的；要不要像手机号、邮箱那样只报不显示，和"不带标签的手写联系方式是否拦截"一起定。
- 检查认不出的手写号码（座机、不带标签的账号）会被数字检查当成"编的数字"引用出来，也属于上面那条 P3。
- 档案的联系方式字段是否拒绝换行、控制字符：没有做，记在路线图"待办"。
