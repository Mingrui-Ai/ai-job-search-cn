## 完成

1. **经历的 hints 全空**。原因：规则只按技能的 `used_in` 找经历，档案的 `used_in` 全空时就没有提示。
   - `score._experience`：先列技能 `used_in` 指向的经历，再列 `name`、`role`、`bullets` 里写到这个技能（同名或同义）的经历，每段经历只列一次。找技能用 `jd_parser.skill_mentions`：从 `material.py` 原来的 `_skills_in` 提出来的同一段逻辑，长词先占位（"Spring Boot"不再算一次"Spring"），两处共用。
   - `score_job` 保留上一份记录里 Agent 补的经历时，`hints` 换成规则现在给的。不这样做，旧记录重新评分后保留的仍是旧 `hints`，`match validate` 会一直报 `experience.hints` 和规则不一致，重新评分也消不掉。
   - 建档工作流（`docs/cn/profile-setup.md`）第 2 步：技能栏里的技能也把 `used_in` 指向用过它的经历；第 3 步：展示技能时，`used_in` 为空的逐个问用户，材料看不出、用户没说的不推断。
2. **notes.md 新旧说法并存**：建档工作流第 5 步补一段：偏好变了的，追加偏好记录以后，再看正文其他小节有没有对不上的旧说法，有就把旧句和建议的新写法给用户看，用户同意才改正文；偏好记录的旧条目仍然不改。
3. **只改其中几项权重时怎么分摊**：`docs/cn/match.md` 换算规则第 1 步、"直接给数字"一行，以及新加的"在试算上接着改"例子；`docs/cn/m2-5-round2-checklist.md` 第 5 步加一条。

## 决策

- **hints 不加 `rules_version`**：它只给 Agent 参考，不进任何维度分数、总分和缺口（加了测试：去掉经历描述，除 `hints` 和档案摘要以外整份记录不变）。`rules_version` 一加，已保存的记录全部过期，Agent 补的经历要清空重补，代价落在用户身上，换来的只是提示更新；和"只改理由的措辞时不加"同样处理。已保存的记录在下次 `match score` 时换上新的 `hints`。match.md 的 `rules_version` 说明和 score.py 的注释都写上了。
- **hints 也看经历的名称和身份**，不只看 bullets：项目名称（"基于 Java 的……"）、身份（"Java 开发实习生"）写到的技能同样是这段经历用过的，只是提示，多列不影响分数。
- **只给几项权重时，其余按"现在的占比"分摊剩下的，"现在"在试算上接着改时指那组试算**。理由：
  - 代码里没有分摊逻辑：`match list --weights` 和 `target.weights` 都要求五项写全，换算全由 Agent 按 match.md 做。所以"和现有行为一致"只能是和现有的换算规则一致：第 3 步写的是"按它们现在的占比分"，"按当前需求调整权重（M2-6d）"一节写的是"没提到的按原比例分摊差额"（规划者 2026-10-30 按 V14 裁定）。
  - "保持不变"做不到：用户给的数改了合计，没提到的几项都不动就凑不成 100，只能把差额挤到某一项上，这会改变用户没提的几项之间的比例；第二轮里 Agent 就是这样做的（两项留在原数、余数全给第三项）。
  - 用户想让某项不动，可以说"不变"，按换算规则第 2 步处理。
  - 第二轮经理已经确认的那组权重不改：那是经理看过并确认的数字，这里只把以后的写法说清。
- 例子用虚构的两步（默认权重 → "方向不太在乎" 35 / 12 / 29 / 12 / 12 → "地点改成 25" 30 / 10 / 25 / 10 / 25），不用经理的权重。
