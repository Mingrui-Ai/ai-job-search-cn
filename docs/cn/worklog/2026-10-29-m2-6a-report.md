## 关键决策

- **反馈表多了第一列"岗位id"**：任务单写"前几列是岗位、公司……"。同一公司可能有同名岗位，Agent 读回反馈表时要靠 id 对上记录。
- **等级显示为"较匹配（good）"**：中文名是我起的（很匹配、较匹配、一般、较弱、不匹配、不符合硬性条件），英文代码保留，和 `match list`、文档对得上。规划者同意，要求对照表放在 match.md 作为唯一出处：表已加在"总分、等级和缺口"里，评分工作流第 6 步引用它，报告页的说明由代码按分档生成，测试核对 match.md 的表和代码一致。
- **"怎么确认"按理由判断哪一方没写**：`match.py` 的未知理由统一写"JD 没写……""档案没写……"（H17），报告按这两个说法给出"先看原文、再问 HR"或"补档案"；两者都没有时写"对照理由核对"。M2-6c 新增的检查只要沿用这个说法就能对上。规划者同意，要求钉住这层依赖：`ReasonWording` 对每一项检查分别让 JD 一方、档案一方不写，核对理由里的说法和报告给的做法，措辞一改测试就失败（以后可以考虑让过滤结果直接带"缺哪一方"的字段）。维度为 null 时按原因给做法：经历、方向让 Agent 补（档案缺内容时补档案），薪资面议问 HR 薪资范围、单位不同改档案的单位。
- **以后的检查和维度不用改报告**：标签表里没有的检查或维度直接显示代码名，权重和维度按记录里的顺序列出。M2-6b 加 `location` 维度、M2-6c 加两项检查后，报告照常可用，只是缺中文名（加一行即可）。
- **CSV 防公式**：任何一格以 `=`、`+`、`-`、`@`（或制表符、回车）开头时前面加 `'`，否则 Excel 会当公式执行。最初只处理了标题和公司；规划者要求所有来自 JD 的文本列都做，于是改成每一格都过一遍（反馈表里来自 JD 的只有岗位和公司，理由和原文片段只在 HTML 里，HTML 全部转义）。
- **只读**：过期的记录照样列出、标红并提醒重新评分，不替用户重新评分。指定的 id 没有记录时报错退出，不静默跳过。

- `tests/test_cn_report.py` 21 项：4 份样例 JD × 示例档案 tech（其中 2 份用 M2-4c 冻结的经历判断补全后经 `match save` 保存），通过真实 CLI 生成报告：
