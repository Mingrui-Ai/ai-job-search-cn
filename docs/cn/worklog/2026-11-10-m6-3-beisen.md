# 2026-11-10 · M6-3 北森招聘门户适配器

- `collect beisen`：读一家北森门户（`<子域名>.zhiye.com`）的公开岗位，新版（单页应用）和旧版（服务端渲染）都支持。租户、门户版本、频道、城市、条款链接和核查日期写在用户本机的 `<数据目录>/collect/beisen.json`，不在名单里的租户在打开浏览器前拒绝。用法见 [采集说明](../collect.md#北森招聘门户collect-beisenm6-3)。PR #PRNUM。

- 浏览器驱动：只对声明了 `CAPTURE` 的站点，被动记下本标签页同源 xhr/fetch 响应里路径匹配的那几个，读出请求体和响应体；不发送、不改写任何请求。协议、主机和端口必须与当前门户相同，排除其他租户。
- Job Schema：`source.site` 为 `ats` 时允许写 `site_job_id`，但必须是 `<平台>.<租户>.<ID>`；收件夹、批次初筛和岗位库沿用它做第一依据去重。
- 测试 `tests/test_cn_beisen.py`：手写的虚构列表响应、页面和正文，离线覆盖面议薪资、多城市、两个频道、最后一页、403、接口报错、跳登录页、连续两次空加载、缺薪资、白名单拒绝、按 `site_job_id` 去重、关键词分组、旧版翻页和详情。
- 收尾补齐：错误类型的频道配置返回校验错误；缺少关键词证据、响应无法解析或列表形状不明确时停止；两次可识别的空加载按剩余总数停止；每组搜索单独判断翻页进展，避免其他关键词读过的岗位造成提前停止。新增离线覆盖跨租户响应隔离、429/验证码、详情接口报错、默认三十条详情上限、配置的多城市搜索和不同租户同号不碰撞。

## 来源核查（平台层面）

- 依据 2026-11-09 的来源调研（仓库外的调研报告和证据，本机保存，不进仓库）：抽查的北森门户隐私政策都是同一份平台模板，没有爬虫、抓取或自动访问方面的禁止条款；robots.txt 为 `User-agent: *` / `Allow: /`；列表和详情不登录就能看。
- 经理意见书-011、012：协议不禁止、信息可靠的来源可以自动采集，进公开仓库。北森作为平台可以接入，但每家公司门户还要单独核对它自己的条款：没有禁止才写进本机白名单，并记下条款链接和日期。公开仓库不写任何真实公司名，示例只用虚构租户。
- 本任务没有访问任何真实北森门户；字段和结构依据调研时保存的页面（只看结构，不复制原文）。

## 决策

- 读取方式：新版门户的列表卡片没有链接，岗位 ID 只在页面自己的列表请求响应里，所以由浏览器被动记下这个响应（规划者已定：不自己构造、调用接口）。详情页从 DOM 读。
- 岗位 ID 用 `beisen.<子域名>.<ID>`，没有用任务单举例的 `<子域名>:<ID>`：冒号不在 `site_job_id` 的字符集里，而且收件文件名就是岗位 ID，Windows 文件名里的冒号会变成 NTFS 备用数据流；加上平台名，是为了以后 Moka 等其他招聘系统的租户同名时也不撞。
- 新版列表的结束以页面自己的总数（列表响应的总数，否则“共 N 个”）为准：调研样本里有一页尚未加载全部岗位就显示结束标记，只看这个标记会漏掉后面的岗位。总数显示还有、却连续两次加载都没有新岗位时，按“页面结构变了”停下。
- 上限按一次运行合计：所有频道、城市、关键词共 5 次列表加载、30 个详情页。没轮到的组在结果里标 `not_run`。`RULES_VERSION` 不变。

## 遗留

- 新版门户的列表响应形状调研时没有记录（只记了请求的键），解析按 `Data` 或 `Data` 里唯一的列表、`JobAdId`/`Id`、`JobAdName`/`Name` 宽松读取，认不出就停。新版是否接受地址里的 `KeyWords`、滚动能否加载第 21 个以后的岗位，旧版详情页的结构，都要等第一次真实运行确认。
- 标题里带薪资（如“（15k-25k）”）时，`jd parse` 会把它当薪资，即使详情写着“面议”；这是解析器的现有规则，适配器只交正文，没有改。
