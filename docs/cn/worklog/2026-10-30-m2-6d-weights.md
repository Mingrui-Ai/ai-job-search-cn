**规划者裁定（2026-10-30）**

- 问题：`profile_hash` 原来包含 `target.weights`。改了权重以后重新评分，摘要变了，Agent 补的经历和方向会被清空，第 3 步要全部重做；验收要求"试算和改了权重之后重新评分排序一致"，只有 Agent 重判出同样的分数才成立。
- 裁定选 A：`profile_hash` 不含 `target.weights`；过期的条件是"摘要不同，或者记录里的 `weights` 和档案现在的权重不同"；`match list` 和报告要能分清"因为权重改过而过期"和"档案内容改过"；`match validate` 报权重在评分后改过；重新评分保留经历和方向，只按新权重重算总分。摘要定义变了会让已保存的记录一次性全部过期，这个代价接受；评分结果没变，`RULES_VERSION` 不加。
- 我提的打算都同意：`--weights` 用 `key=value`；五项都要写，和 `profile validate` 共用检查；输出加 `trial`、`saved`；不写文件，格式错时退出码 2；报告里不加试算；"评一批岗位前"单独一节，后面的步骤不重新编号；换算规则照提议的做。
- 规划者的建议（采纳）：给用户看新权重时同时写出各项的占比，因为"只改提到的那项"以后五项之和就不是 100 了。占比由试算输出（`shares`），Agent 照抄，不自己算。

**完成**

  - 输出最前面是 `trial`：`note`（说明是试算）、`weights` 和 `shares`、`profile`（档案现在的权重和占比）；每行多一个 `saved`（已保存的等级和总分）；

- 权重检查抽成 `profile.weight_errors(weights, path)`，`profile validate` 和 `--weights` 共用。少一项时的报错改成 `missing; name all five (…)`，直接说出五项是哪些。

**决策**

- 换算规则最初只改用户提到的维度，没提到的数字不动，理由是 V14 要看"相对默认权重调高、调低还是不变"，按比例重新分配成 100 会让没提到的数字也变小。V14 的对照（#77）发现这样不对，规划者已经改了裁定，见下一节。
- 最初的换算按顺序做：先降"不太在乎"的，再升"其次"的（不调高的各项里最大的数 + 5），最后升"最看重"的（其余各项里最大的数 + 10）。
- "只说不想要什么"先问清是硬性条件还是偏好：硬性的（看到就不投）改 `relocate`、`exclusions`、`salary_min`，按建档工作流改；能投但排后面的才是权重。
- 说的不是这五项的（大厂、转正、成长）不硬套进某一项。
- 报告不显示试算：报告和反馈表是让用户对已保存的结论表态的，混进试算的总分，就分不清哪个是真的。
- `cn-match` 原来只允许写草稿。新的一步要在用户确认以后写档案的权重和偏好记录，所以两个入口写明这一例外；硬性条件的字段仍按建档工作流改。

**V14 的对照和新的换算规则（2026-10-30）**

- V14（Codex A，#77）对照的是 `eb0ef30`：
  - 6 条说法里，三条清楚的大小关系 12/12 符合，增减方向 13/15 符合；三条该追问的都先追问了；
  - 两条完整流程通过：试算不写文件，确认后只改权重并追加偏好记录，旧记录只因 `weights` 过期，重新评分以后经历保留、排序和试算一致。
- 两项 P2：
  - 用户说"方向那份别动"，方向的数字没动，占比却因为别的项变了，从 25% 变成 27.8%；
  - 用户说两项都比原来高一点，其中技能本来就最大，按"本来就更大的不动"没有提高。
- 规划者裁定（只改文档）：
  - 写进档案的五项权重是合计 100 的整数，数字就是占比，给用户看时只说百分之几；
  - 换算后要同时满足：提高的项占比更高，降低的更低，说"不变"的不变，最看重的高于其他每一项，没提到的按原比例分摊差额，取整的差额加减在没提到的项里最大的一项上；
  - 用户直接给的数字合计不是 100 时，按比例换算成合计 100，给用户确认；
  - `match list --weights` 仍接受任意非负数。
- 新规则怎么定的：
  - 提到的项先定：不变的照旧，完全不看的 0，不太在乎的减半，其次、也看重的 + 10，最看重的 + 20（两项一样最看重时，都取较大的 + 10）；
  - 没提到的分摊剩下的；
  - 最后核对四条，最看重的不是最高时再加 5 重新分摊；
  - 五项都提到了时，把要提高和要降低的各项按比例缩放到合计 100。
- 例子用一段临时脚本按这些步骤核对过，脚本不进仓库。脚本还核对了另外几种说法：两项都提高、两项一样最看重、五项都提到了，以及现在的权重很偏（技能 60）时最看重地点。结果都满足四条。文档里的例子没有用 V14 样例的说法。

**M2-5 第二轮的操作清单（草稿，规划者 2026-10-30 要的）**

前提：
- M2-6c、M2-6d 都已合并；
- 主工作树 `cn` 切回 master 并拉取最新（现在停在 `feat/cn-m2-6d-weights` 上）；
- 在 conda 环境 `ai-job-search-cn` 里运行；真实数据在默认的 `data/` 下。

**顺序很重要：先改档案内容，再补经历，最后调权重。** 档案内容（薪资、城市等）改了会清空 Agent 补的经历；只改权重不会。

1. **看现状**：
   - `python -m jobsearch_cn profile validate`：预计报 `availability.acceptable_cities: missing`；自己写过 `weights` 的还会报 `target.weights.location: missing`；
   - `python -m jobsearch_cn match list`：旧记录全部过期，`stale_reasons` 里有 `rules` 和 `profile`。
2. **补档案内容**（对 Agent 说"更新档案"，走建档工作流）：
   - `target.salary_min`：最低期望薪资。实习按天填（`CNY/day`），和 JD 的单位一致才能比较；
   - `availability.acceptable_cities`：可以接受、但不是首选的城市，没有就填 `[]`；
   - `availability.remote_ok`、`relocate`：还空着的补上；
   - `availability.start_date`：M2-6c 的到岗时间检查要用，没填的补上；
   - 自己写过 `weights` 的：先补上 `"location"`（写 0 就和以前一样），或者改回 null，第 4 步再调；
   - 每改一项，Agent 在 `notes.md` 的"偏好记录"记一条。最后 `profile validate` 要通过。
3. **全部重新评分，补经历**（对 Agent 说"给已保存的岗位重新评分"，走评分工作流第 2–5 步）：
   - 规则版本和摘要都变了，旧记录里 Agent 补的经历已经清空，每个岗位都要重新补一次：`match score <id> --draft` → 补经历 → `match validate` → 抄 `total` → `match save`；
   - 做完以后，`match list` 里不应再有 `stale` 的记录；
   - 待定：M2-6c 合并以后，旧的岗位记录要不要重新导入，才能读出面试形式和到岗时间？按 M2-6c 的说明做。
4. **调权重**（对 Agent 说"我现在更看重……"，走评分工作流的"评一批岗位前"）：
   - Agent 换算，用 `match list --weights …` 试算，给用户看数字、占比和排序的变化；
   - 用户确认后写 `target.weights`、记偏好记录，再跑 `profile validate`；
   - 不想调就跳过这一步。
5. **只因权重过期的记录重新评分**：`match list` 里 `stale_reasons` 只有 `weights` 的，逐个运行 `match score <id> --save`。经历保留，每个几秒钟。做完以后 `match list` 的排序和第 4 步的试算一致。
6. **出报告、填反馈**：
   - 运行 `match report`；
   - 用浏览器打开 `report.html`，用 Excel 或 WPS 打开 `feedback.csv`，填好三列；
   - 告诉 Agent，由它汇总认可的情况。

顺不顺手（给规划者参考）：
- 第 3 步最费事：每个岗位都要 Agent 重新补经历。真实岗位只有 5 个左右，还能接受。这是 #68（规则版本 4）和 M2-6d（摘要的定义）带来的一次性代价，以后只改权重就不会再清空了。
- 第 5 步要逐个岗位运行 `match score --save`，岗位一多就麻烦。以后可以考虑加一个命令，把只因权重过期的记录一次重新评分。本 PR 不做。
- 顺序是个坑：先补了经历，再改薪资或城市，经历就会被清空。所以清单把档案内容放在最前面；match.md 第 7 条也写明了原因不同、做法不同。
- 在 Windows PowerShell 5.1 里，`--weights skills=30,direction=25,...` 不加引号也能整个传进去（本机试过），不需要额外提示。
