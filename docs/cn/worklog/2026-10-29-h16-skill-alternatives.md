# 2026-10-29 · H16：任选其一的技能（Claude A 会话，PR #59）

**完成**

- Job Schema：`requirements` 新增 `skill_alternatives`，是技能组的列表，例如 `[["Golang", "Java"]]`，JD 没给选择时为 `[]`。
  - `jd validate` 检查：每组至少两个技能、组内不重复；组里的技能必须也在 `requirements.skills` 里；一个技能最多在一组；
  - 出处 `evidence["requirements.skill_alternatives"]`：每组的技能必须一起出现在同一个出处片段里，只出现在不同片段里不算，证明"选一个"是 JD 说的；
  - 只是加字段，`schema_version` 仍为 1。`schema.upgrade()` 给岗位库里这之前存的记录补上 `[]`，`Store.get`、`Store.all` 读出时调用；重新导入时，技能和技能组如果来自不同的记录、对不上了，技能组跟着技能所在的那份记录走（`store._fit_alternatives`），免得合并出无效记录。
- `jd parse`（`jd_parser._alternatives`）：
  - 只看同一分句里紧挨着的技能（"串"）：技能之间只能是"、""/""或""或者"，技能后面可以带"语言""框架""软件""工具"；
  - 串里有"或"就成组；否则串的前后 15 个字以内有"任一""任选其一""其一""之一""其中之一""二选一""任意一种""至少（掌握）一门 / 一种 / 一项 / 一款""一门即可"也成组，中间不能有"和""及""与""并""是""为"；
  - 串后面跟"专业"（"机器学习或数据分析相关专业"）、前面是"专业："的不成组；
  - 同义写法只算一个（"Go 或 Golang"不成组）；和前面的组有重叠的不再成组（同一句话写两遍只记一次）；
  - 出处是这一串所在的分句，分句太长时只取这一串。
- 评分（`score.py`）：
  - `_requirements()` 把 JD 的技能整理成"要求项"：一组算一项；组里的技能在 JD 别处又出现（`boss_intern` 职责里的 Go 和要求里的"Golang 或 Java"），只在组里算；两组有同一个技能（含同义写法）时并成一组；只用 `requirements.skills` 里有的技能；
  - 技能分：每项取组里得分最高的技能，`matched`、`missing` 里写成"Golang 或 Java"，理由加"（其中 N 项任选其一）"；
  - 方向：一组按组里技能所属的分组各计 1 次（`general` 照常不计）；
  - 缺口：一组只在一个都没有时列一条，出处取写着整组的那个片段；
  - `RULES_VERSION` 1 → 2，按 #54 的口径：维度分数和缺口变了。
- 文档：job-schema.md（字段表、新一节"任选其一的技能"、出处规则、版本记录）、jd-parse.md（识别表新增一行，局限里写明口径）、match.md（维度表、缺口、`rules_version`、新一节"任选其一的技能（H16）"）、jd-import.md（补全步骤提到这个字段）。

**决策**

- 字段名用 `skill_alternatives`，结构是"列表的列表"，和 `skills` 一样只存技能名，不另设对象。Agent 补、改时最不容易写错，出处规则也能沿用"列表字段"的做法。
- Job Schema 版本号不升。只加了一个字段，旧记录在岗位库里读出时补 `[]`；`jd validate` 对手写的、没有这个字段的记录仍然报 missing，保持"所有字段必须出现"的约定。
- 组里的技能在别处又出现时只按组算。JD 的要求部分写明了会一个就行，职责里提到 Go 是在说岗位用什么，不是另一项要求。
- "均可""都可以"不当标记：它们也常用来说两个都要会。"Python 和 Java 其中之一"有"和"，不成组；宁可漏读，交给 Agent 补。
- "PS 或 AI"读不出，词表里没有这两个缩写。"AI"在 JD 里多指人工智能，"PS："常是附言，加进词表会多读，所以这次没有加；写成"Photoshop 或 Illustrator"可以读出。要不要加，请规划者定。
- 不看 V8：写规则时只用任务单列的写法和自己编的句子，没有看 `cn-codex`，也没有看 `codex/v8-*`。
