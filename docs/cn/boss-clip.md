# BOSS 直聘一键收藏插件（boss-clip）

平常在 BOSS 直聘上浏览时，看到想要的岗位，点一下浏览器工具栏上的插件按钮，就把**眼前这一页**存进工具的收件夹，之后用 `jd screen` 照常过滤评分。

- **详情页**（`www.zhipin.com/job_detail/<ID>.html`）：存这一个岗位，内容是岗位自己的文字（职位名、薪资、标签、职位描述、工作地址、公司），不含招聘者、在线状态、相似职位（[screen.md 2.3](screen.md#23-text-写什么)）。
- **搜索结果列表页**：存页面上已经加载出来的每张岗位卡片的链接和摘要（职位名、薪资、地点、标签、公司）。卡片只有摘要，评分时信息少；以后打开这个岗位的详情页再点一次，导入时会用详情的全文替换（按岗位 ID 去重，[screen.md 第 3 节](screen.md#3-去重)）。反过来，库里已有的岗位不会被卡片改动，详情的全文不会变回摘要；卡片上的变化（比如薪资）也不写入，`jd screen` 的 `warnings` 里会有一条 `summary_kept`，想刷新就存一次详情页。
- 插件**只在你点按钮时**读当前页面，不翻页、不滚动、不打开别的页、不点任何按钮、不联网、不用 `chrome.debugger`。页面有验证码、被登录弹窗或登录表单挡住（后面还留着旧岗位也一样）、没登录也没有岗位内容、岗位已关闭、职位名是空的或读不到职位描述（页面还没加载完，描述栏只有"职位描述""岗位职责"这样的标题或"加载中"也算）、不是 BOSS 的页面时什么也不存，按钮上显示红色 `×`，鼠标停在按钮上能看到原因。只有页头的"登录"链接、页面照常显示岗位时可以存；隐藏着的登录弹窗不算。判断只看页面结构，职位描述里写到"登录""验证码"不受影响。存成功时按钮上显示存了几个。
- 代码在仓库的 [extensions/boss-clip/](../../extensions/boss-clip/)，权限只有三项：`activeTab`（点按钮那一下读当前标签页）、`scripting`（把读取页面的脚本放进这个标签页）、`downloads`（把文件存进下载目录）。没有 `<all_urls>`，没有常驻页面的脚本。

## 1. 安装（一次）

在专用的 Chrome 或你平常用的 Chrome 里都可以（Edge 也一样，菜单名称略有不同）。

1. 地址栏打开 `chrome://extensions`；
2. 打开右上角的"**开发者模式**"；
3. 点"**加载已解压的扩展程序**"，选仓库里的 `extensions/boss-clip` 文件夹；
4. 点地址栏右边的拼图图标，把"BOSS 一键收藏（jobsearch_cn）"**固定**到工具栏。

插件存文件走浏览器的下载功能，存在 `<下载目录>/jobsearch-boss-clip/` 下面，一个岗位一个 `.json` 文件。如果你在 Chrome 设置里打开了"下载前询问每个文件的保存位置"，可能每次都会弹出保存框，关掉这一项即可。浏览器的下载列表里会出现这些文件，这是正常的，可以随时清除记录（不影响文件）。

更新插件：仓库更新后，在 `chrome://extensions` 里点这个插件的刷新按钮。卸载：点"移除"。

## 2. 用法

1. 在 BOSS 上正常浏览，在详情页或搜索结果页点插件按钮。可以点很多次、跨很多天，文件都攒在 `jobsearch-boss-clip/` 里；
2. 想筛的时候，告诉 Agent"筛一下我收藏的岗位"，或者自己运行：

```text
python -m jobsearch_cn jd inbox-import [文件夹] [--site boss] [--data-dir 数据目录]
python -m jobsearch_cn jd screen <上一步输出的 batch> --data-dir <这次用的数据目录>
```

`jd inbox-import` 把文件夹（默认 `~/Downloads/jobsearch-boss-clip`；下载目录改过位置的，写上实际的文件夹）里格式正确的 `.json` 搬进新批次 `<数据目录>/inbox/boss/<YYYYMMDD-HHMMSS>/`，搬走以后原文件夹就空了，下次收藏从头攒。

- 每个文件按 `jd screen` 的同一套格式检查（[screen.md 2.2](screen.md#22-json-文件采集程序用)）；不合格的、不是 `.json` 的、下载到一半的（`.crdownload`）留在原处，列在输出的 `left` 里，带原因；
- 输出：`folder`、`batch`（新批次的路径，没有可搬的文件时为 null，也不建文件夹）、`moved`、`files`、`left`、`next`（下一步的 `jd screen` 命令，批次和数据目录都写成带引号的绝对路径，可以直接运行，岗位和评分记录都进这次的数据目录，不看下一次运行时的环境变量）；
- 退出码：0 搬了至少一个文件；1 一个都没搬；2 文件夹不存在或是链接、数据目录下的文件夹是链接、参数写错。

文件名是 `<点击时间>-<岗位 ID>.json`，按名字排序就是点击的先后。同一个岗位不管先存卡片还是先存详情，同一批或分开几批，最后留下的都是详情。

## 3. 页面结构变了怎么办

选择器都在 [clip.js](../../extensions/boss-clip/clip.js) 的 `SELECTORS` 里，规则和 M6-3 采集程序的 `boss.py`（PR #142）相同，每条规则按顺序试、第一个匹配的生效。插件读不到职位名、职位描述或卡片时会显示 `×` 和原因；把那一页另存为 HTML（去掉个人信息）交给开发会话，改 `SELECTORS` 和 [离线测试](../../tests/test_cn_boss_clip.py) 即可。列表卡片上的标签和公司名（`card_tags`、`card_company`）是按常见写法猜的，还没在真实页面上核对过。

描述栏如果整段只有标题和常见加载、等待提示（如“正在加载，请稍候…”、“Loading, please wait…”），不会生成可覆盖旧岗位的详情文件。检查忽略提示中的标点、换行和进度数字；“写周报”“Write SQL”等短职责仍可保存，真实职责里提到加载或等待组件也可保存。这是针对常见占位提示的检查，不能保证识别网站未来所有提示文案。
